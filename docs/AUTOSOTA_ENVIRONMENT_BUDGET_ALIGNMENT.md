## 1. 优先消费者探针，不默认重装

Init 和环境规划提示明确：先判断当前解释器及只读依赖是否适用，执行有限消费者操作；错误证明缺失或冲突后才增量修复。不按仓库名字选择底座。

- 可选已有 run-owned 解释器，计划采用 `base_environment_mode: "existing"`、`commands: []`，仍必须有真实消费者探针。
- 外部环境继续通过只读 overlay 连接，不直接允许安装命令回写旧环境；clone/reconstruct 保留为需要证据的备选。
- `existing` 不接受外部解释器冒充本次前缀，不因“Python 文件存在”就判定仿真就绪。
- import 成功只是局部证明。正式验收仍需 reset/step/render、采集、训练、实际加载与 rollout/指标链路。

实现：`provision.py` 的规划提示、提案校验与既有构建通路；`agent_roles.py` 的 Init 指引。外部资源隔离仍见 [受控环境复用](CONTROLLED_ENVIRONMENT_REUSE.md)。

## 2. 复用源码交接结论，不复用伪造的实验完成状态

`selected_path.json` 的缓存身份包含执行声明、任务、源码身份和相关入口文件摘要；原先只根据声明判定不变的旧缓存需要重新核验一次。

训练保存与评测加载的正向源码审核存入 `handoff_reviews/<digest>.json`。相同来源和输入可复用；入口内容变化后重新审核，坏缓存不作为成功结论。Init 规划收到已选择的阶段、所需资源及交接原因，避免在同一次环境规划前重复购买相同检查。

这只是源码级连接审核，不是 checkpoint 已产出、实际加载成功或分数有效的证明；原生身份核验与评测合同继续执行。

## 3. 错误计划先反馈给规划者，不能把类型错误抛给外层

此次真实故障由列表中的对象进入 `set()` 导致 `TypeError: unhashable type: 'dict'`。现在先验证 JSON 对象、命令/探针/绑定 ID 列表及字符串字段，再转换占位符和执行成员检查。

格式不符合合同会返回具体字段和索引，例如 `commands[0] must be a non-empty string`，在原有有限纠错轮次内要求 Init 修正。纠错耗尽则封存稳定的 `framework_plan` 证据，标明 `repair_owner=environment_planner`、`native_operation_status=not_started`，不能声称安装失败或环境不可运行。RUN 在这种框架失败时不额外购买叙述回合。

没有放开任意命令、延长无限重试或取消资源审批。模型决定可执行方案，执行器继续验证安全合同。

## 4. 预留只靠可信回执核清

总模型上限和历史计费依据保持不变。`budget_receipts.py` 在新回合 admission 前、受控结算等待时核查预留；也支持不修改账本的 dry-run。

核清必须匹配本 run 的 reservation/session/role、预算归属、稳定执行 attempt ID，以及当前冻结计费口径和 price card；进程仍活跃或身份不可核实则保留。读取只限本 run 的执行器 JSON 回执，大小与路径受限，支持 Recorder 等嵌套 worker 的根相对引用。

| 可信证据 | 账本结果 |
| --- | --- |
| 进程已不存在；同一回合官方价格网关有完整用量与匹配费用 | 按真实回执结算，释放该回合预留 |
| 同一网关明确证明没有转发请求，费用/held/ceiling 都为零 | 零费用结算；不是因为进程死亡猜测零 |
| 实际用量未知，但网关有可信且不大于旧预留的请求上界 | 保留 unknown，可缩到已证明的上界 |
| 缺回执、归属不符、活进程、计费口径不符 | 保留原预留，报告不能核清的原因 |

中断也尽量封存网关计费回执，已知消耗正常计入；无法封存或验证就保守保留。不会使用 Claude CLI 的显示价格替换 DeepSeek 官方估算，也不对旧未知用量事后猜价。审计重复执行不会重复结算。

## 5. 报告不能挤占恢复额度

可在本 run 的 `scheduler_policy.json` 配置 `recovery_model_reserve_usd`，默认 `min($2, 总上限的 10%)`。这是现有总额度内留给执行/修复的空间，不增加上限。Recorder admission 和扩额均受锁内校验，不能侵占；Scheduler、Init、Fix 仍使用正常可用额度。

Recorder 在开始写作、读取技能后、异步启动前重新读当前账本。低于恢复保留额度时不买写作回合，仍用确定性事实更新 RUN.md；写作建议可以保留，但不能充当最新事实。此保护针对 Recorder，不等于已实施所有模型角色的优先级队列。

RUN 展示已结算、尚未结算预留、用量未知预留、当前可用额度及账本更新时间。`reserved` 不证明进程仍活着。停止后余额回升也不表示实验已自动恢复。
