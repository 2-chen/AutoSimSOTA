# 训练产物交接与存储安全

本次修复针对两类系统故障：将任意一个正更新计数当作本轮终点；忽略频繁保存大型训练状态的空间成本。

## 不再把“加载正确”当作“选择正确”

Supervisor 读取完整、稳定排序的数字元数据目录，结合实际调用和生产者源码解释训练终点或原生 best 规则。竞争计数需显式审阅，较小计数不能冒充终点；超安全扫描预算明确报告缺口。这里只比较计数证据，不按正式测试分数选 checkpoint，也不从文件名猜 best。

执行器用最近且无歧义的共享容器关联策略与计数，不要求固定目录层级。仍由 Agent 解释保存/加载语义；引用、目录边界和实际加载身份由执行器验证。

## 已经测错权重时，不必重训

Main 的 `research_progress.handoff_corrections` 提供疑似错误交接的短清单。主 Agent 可以调用 `correct_policy_handoff(label)`，重新审核已完成训练并仅运行评测。新选择放入独立文件，测量使用 `<label>_handoff_correction`，附原测量/选择/训练回执的关联及指纹。

原分数保留，因为它确实测量了当时加载的策略。新分数不能悄悄替换基线或 incumbent；后续研究需要结合原协议明确解释纠正结果。该恢复入口目前针对可独立核验的原生训练回执，不适用于任意图执行产物。

## 空间成本也属于资源规划

原生阶段启动前检查实际输出文件系统。默认最低余量：训练、采集、数据准备 2 GiB；其他阶段 256 MiB。`AUTOSIM_MIN_FREE_STORAGE_BYTES` 可配置最低余量，必须非负；这不是空间预留，不能证明整个长期作业容得下。

Agent 可在 native job 的 `resources` 中声明正整数 `storage_required_bytes`；执行器检查不低于安全余量和预计需求。技能指导根据一次保存的权重、optimizer/RNG、保存次数、冻结副本及媒体估算需求。它不会自动改保存频率或删除产物。

`validating-policy-training`、`control-same-budget` 已增加交接诊断、复用与存储规划指引。仍使用短目录→Agent 选择并说明理由→读取正文，不向每次调用灌入整套技能。

## 验证边界

合同测试覆盖完整目录、计数冲突、可变目录层级、同目标别名、存储阻塞与输入校验，以及纠正只执行评测、保留原选择/原测量。历史文件诊断识别出 RoboSyn round_4 的 1000 步误选择和已有 8192 步终点。

这些检查不是实际增分证据。磁盘写满后原控制器已暂停；实验快照未删除，正确终点策略尚待重新评测。
