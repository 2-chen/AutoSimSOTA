# RoboSyn 强制数据对照：前瞻开发轨道

2026-10-13用户明确授权另立前瞻轨道，继承原研究全部账本，不增加模型、GPU或墙钟总额度。旧run、20%/30%等开发成绩、全部失败和确认记录保留。当前模型统一deepseek-flash。操作者复用工程源码、环境和只读资源的干预需单列；本轨道不冒充零干预冻结trial。

## 必须达成的目标

本轨道以`--require-data-comparison`冻结目标：真实完成随机获取与失败定向获取的数据比较，或对无法完成的实际arm形成有正面证据、独立审核的边界。参数优化成绩不能替代数据结果；空campaign不能进入独立确认。预算确实耗尽时如实保留未完成项，不靠删arm、改目标或刷新额度收尾。

主Agent负责完整链路，Data持续提出采集、质量、筛选及消费方案，Resource按实际吞吐分配局部预算，Fix修复错误并复验原操作。操作者不指定采集数、失败目标、训练步数、种子、策略或checkpoint。优先小规模完整链路，不先铺开大矩阵；关键资源需覆盖采集、处理、训练、评测和恢复，而不是仅覆盖采集。

## 先修好消费连接，再投入长作业

父run真实2k训练的封存日志发现：marker由多进程交错打印，部分不是单条JSON；记录缺`consumption_stage`和稳定`reader_id`；`setting=random`是场景名，不是被选data-version的输入key；数据ID由路径猜测不能代替注册身份。父run分数可保留为开发观察，但没有正式数据消费认证。

请Init/Data/Fix自主阅读当前训练源码及安装trainer的真实ABI，修复原生适配器，在冻结本轨道源码/协议和长期正式训练前做廉价真实batch小试：

- 通过经过核验的原生参数显式路由被选注册版本ID及输入key；框架解析的data-version路径只是选择，不能宣称实际消费。元数据标签不是期望hash或计数，字节身份须由实际打开的数据重新计算。
- 区分DataLoader读取与真正参与update的训练batch；计数来自实际样本/优化调用，不由steps×batch请求值生成。按真实ABI识别batch维度，保留旧/新增来源曝光，unknown不能补成已验证。
- 每个reader生命周期独立身份、单调计数；由单写者或合法原子方式输出完整JSON行，避免每次getitem重复打印造成交错和日志膨胀。多个流不能重复累计相同样本。
- 修后复验同一短操作及严格解析/注册绑定/实际batch门槛。不得手工拆坏行、放宽校验、替原生日志填值，或重训所有历史候选来验证打印。

训练产物需完整bundle→实际加载→rollout→指标的统一身份核验。正式产物加载失败交Fix恢复同producer，先复用已有成功产物，避免重复长训练。新的正式训练在执行前封存选择，失败恢复保持原数据选择和源码身份。

## 最小可信比较

先调查专家/控制器可合法控制哪些训练条件、原生collection_seed如何实际连接及动作是否为正确监督。基于开发失败提出目标，不写死某个任务失败维度。先试少量原生执行和质量检查，核验真实条件、episode谱系、标签、转换、实际消费及策略评分均可完成。

在获取前由Main/Data登记合法v2 campaign：随机质量控制与Agent失败定向arm、共同起点、配方、训练/评测随机性、实际start witness、停止条件及资源口径。先完成最小直接对照，再考虑简单规则、筛选消融、额外种子。请求量、尝试量、完整量、Q0、选择量、实际batch曝光分别记录；等接受量、等采集成本、等完整资源的结论不混用。

MimicGen或DAgger仅在源演示/子任务变换/回放，或策略访问状态的正确动作供给经过核验后使用；普通random专家采集不能改名为这些方法。若这些能力不具备，优先合法条件定向采集/可逆质量筛选，而非以缺少高级方法为由停止基础数据比较。对可修消费者错误使用Fix，不宣称仓库永久不支持。

模型总上限90美元，GPU总上限24小时，墙钟原起点及累计446400秒均继承，不释放缺回执旧预留。长期作业使用现有提交/检查/延期/取消机制；Resource可重分配局部额度但不能扩大总额度。所有失败和成本保留。
