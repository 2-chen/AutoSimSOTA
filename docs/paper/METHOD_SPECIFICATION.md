# AutoSimSOTA 系统方法与 FDAS 数据分支

## 系统级问题与研究动作

系统输入是原生仿真仓库、目标与固定成功定义、可合法连接的资源和有限预算；不要求输入一定有专家、示范或预先整理好的训练模板。Main从源码和真实小试连接可用环境、训练／策略加载及原生评测，建立基线，再在诊断信息、训练经验获取、学习方法／合法部署修改之间自主选择下一次干预。数据分支是具身特色，不是所有任务的必经阶段。

研究状态沿用工作计划、当前能力与前提、真实开发证据、在途作业、产物及成本；观察、原因假设和未验证声明分开。执行器只管理授权／隔离／总额与科学合同，Main选择研究路线，专项角色可选委派而非固定串行流程。一次干预之后保存真实测量、保留或回退并更新简短经验；工程失败进入证据→Fix／参数纠正→原连接复验。没有合法替代时给出受证据支持的边界。

系统效果需以匹配资源的通用研究Agent与autoresearch-robotics对照验证：共同模板内优化和原生仓库接入分别报告，冻结后才测真正未见仓库。研究完成率、首次可信分数时间、最佳指标随完整成本、独立研究重复与人工介入是主要系统单位。软件合同通过、一次部署提分或单个数据arm不能替代该系统验证。当前短提示／按需手册与决策记忆为实现机制，依赖范围复用及自主推进仍需真实纵向验收，不先宣称更快、更通用。

视觉有两种用途：人类展示与Agent研究诊断。后者须有真实支持的模型／工具、合法开发画面及身份、带不确定性的观察，再由Main选择可检验干预；文本模型不能因有PNG路径就声称看图。无视觉或无专家时仍可沿其他可行路线推进。

## FDAS 的定位与输入边界

以下规格只定义选择新增示范／筛选路线时的数据子研究。它的获取矩阵、Q0／Qt和等接受量控制不限制整个系统的合法算法／部署研究；冻结数据专项的旧run仍完成其原承诺，不由本文修改运行协议。

2026-10-15：原生控制、manifest/部分失败、实际batch消费、v2数据对照及报告合同已实现；真实新增数据的公平对照尚未完成。实验分为先获取、后Qt增量两个草案，不因工具允许预登记就声称方法有效。
这里定义研究对象，不把待测机制写成已验证性能结论。

## 输入、决定和输出

输入：隔离仓库 R、合法原始示范 D0、原生专家 E、合法训练域 Ω、开发评测 Vdev、
不可访问的最终评测 Vhold、模型/算力/存储包 B。
专家能力可能是 reset-only、状态恢复接管、轨迹适配或仅人工演示；由实际能力决定可以做什么，不按仓库名字猜。

每轮干预 `h = (g, q, n, m, u)`：

- `g`：有源码/配置路由与有效域的原生采样控制；最小原生试验验证可执行性。
- `q`：任务相关选择规则，与所有方法共同的有效性底线 Q0 分开。
- `n`：接受数量/尝试上限，由产出率、数据基数和剩余资源决定，不固定所有任务采同样数量。
- `m`：官方/新增混合及实际曝光；混合意图与 loader 实际读取分别记录。
- `u`：共同初始化和完成学习量，以实际更新/曝光描述，不以命令启动当完成。

输出：不可覆盖的数据版本、实际消费证据、策略身份与原生测量；拒绝、重复、失败成本和不支持的条件同样保留。

## 失败到可执行获取

成功率0不能推出数据不足。欠训、坐标/时间错配、动作量纲、错误权重或评测接线也可能造成低分，先核验基线。

| 层级 | 示例 | 使用规则 |
| --- | --- | --- |
| 可验观察 | 原生阶段停止、某初始条件失败、动作饱和 | 引用真实封存事件；不是把视频猜测当事实 |
| 原因假设 | 条件覆盖不足、时序信息缺失、纠正机会不足 | 可证伪；必要时安排能区分原因的短诊断 |
| 可执行干预 | 可控姿态/光照/物体/专家参数或数据视图 | 接到原生 collector/loader；无控制接口不能执行 |

研究连接是 `开发观察 → 目标条件 → 原生控制 → 实际数据覆盖 → 策略变化`。
合理解释不等于这条链成立。训练/专家失败动作不能冒充成功标签，评测轨迹不回流训练。

当前 Data/Scheduler 用报告、工作计划、campaign 与原生阶段提出和执行决定。
当前没有通用 failure embedding、学习型价值预测器或已校准的贝叶斯获取函数，论文不能虚构这些模块。

接口实现：原生控制从collection_settings进入独立源审核及专用builder输入，不与评测设置混合；manifest选择只操作真实记录的条件/单位和完整episode身份，不统一数据格式。LeRobot有内置CPU检查；其他格式可由Agent连接source_manifest原生reader，封存检查源码并独立核验其观察。生产失败与完整部分可用性分开，未知标签/来源不推断。coverage对照提供小试反馈，不证明控制因果性或学习型coverage模型。

新前瞻比较使用campaign v2：random_quality、rule_targeted、agent_targeted及固定数据/Qt对照，冻结一条预算轴、共同Q0和学习/评测因素。规则采用原生开发失败频率的固定配额；算法标签不替代native计数/生成使用核验。训练见证区分actual training_batch与预取，累积计数不重复相加。未执行的数据arm不能被提前确认绕过，独立边界是未完成结果而非零分。软件机制不是论文性能贡献证明。

## 方法循环

```text
取得真实共同基线和冻结的开发协议
读取开发 rollout 诊断；未知则安排有界诊断
Data 查证可控条件与专家能力，提出获取/选择假设
Scheduler 预登记 campaign、接受量、随机对照、配方与成本
对每个 arm：
    小试专家 → 有效轨迹 → 转换 → 实际 loader batch
    根据能力和产出率扩大；记录全部尝试/拒绝/重复
    raw 不覆盖，Q0 与任务相关筛选生成独立版本
    混合 D0，实际训练消费并核验完成学习量
    加载这次训练策略，共同开发协议 rollout、计分
    独立检查数量、seed、来源、初始化、曝光和成本
比较结果：改获取假设、扩大、停止获取或尝试其他优化
冻结最终策略后在保留条件上确认，不将确认结果给 Data
```

两个新增数据 arm 共享专家、合法域和 Q0；FDAS 为筛选多采产生的成本不能隐去。
仅有 reset 专家时只能定向初始条件，不能声称中途恢复获取。

## 可投稿的增量必须由什么证明

已有自动生成、失败恢复、策略相关选择研究。“LLM+采集”不是充分新颖性解释。
待证增量是：在不同仓库原生能力约束中，自主生成并执行获取/选择联合干预，
不靠人为写每个 benchmark 的固定研究规则，并相对同资源简单对照有收益。
证据链是实验设施，不应占据全部贡献叙事。

1. 原生条件不同的任务中，失败目标可执行，实际数据覆盖发生相应变化。
2. 首先等接受量比较random_quality/rule_targeted/agent_targeted；获取主表不要求Qt。随后固定同目标获取池比较agent_targeted（Q0）与fdas（额外Qt），分开目标和选择贡献。只完成前者就只主张获取。
3. 固定数据等计算续训不能解释全部收益。
4. 与简单失败频率/覆盖重采样比较，检验 LLM 推理价值，而非只对比随机。
5. 冻结后的未调试任务和独立自主流程重复；有真实留出仓库才称跨仓库迁移。
6. 总成本、负结果、不支持任务与人工干预透明。

只有 collector 接通但没有直接收益对照，应称工程可行性；仅单任务有效则收缩研究范围。

## 当前矩阵合同

[获取草案](EXPERIMENT_MATRIX.json)为4候选任务×5方法×3训练seed：fixed_official、fixed_continuation、random_quality、rule_targeted、agent_targeted，共60个计划单元；正式先准入两任务，未准入任务不直接启动。
[Qt增量草案](EXPERIMENT_MATRIX_QT.json)在相同候选范围上加fdas，共72个计划单元，不新增一行与agent_targeted重复的targeted_quality。两者phase仍draft、bindings为空、未决原生协议保留null，均不是资源授权、已经冻结的研究或实测。
Qt小试冻结共同目标池P和接受量N：Q0控制从P中按预先无关规则取N条，Qt从同池按任务相关规则取N条，两者来源族去重和学习量相同。池构造、N及不足额处理在正式评测前确定；共用池不是独立生成重复，构造/拒绝/额外采样成本单列。Qt不足N时记录未完成，不复制样本或看结果后降低N。
targeted_quality保留为旧研究的合法标签，不追溯重命名历史数据。正式获取设计必须包含匹配的规则控制；旧random/FDAS设计仍可读取。所有正式候选仍需完整协议、初始化前冻结和实际科学审核，formal_paper_eligible不因合同通过而变true。

## 实施位置与验收单位

- Data 调查：`data_agent.py`、Data 角色、按需技能与受控源码读取。
- 决策执行：`main_agent.py`、`prepare.py`、原生 collect/prepare_data/train/evaluate。
- 数据身份/消费：`data_lineage.py`、`data_versions.py`、原生生产者与 loader 见证。
- 假设/对照：`data_campaign.py`；注册不自动批准公平性。
- 计分监督：policy_consumption、receipt_verifier、独立 Supervisor 数据审核。
- 矩阵：`tools/data_study.py`；开发分数不自动进入正式主表。
- 展示：中文 RUN.md、真实原生 demo 与数据/指标图，不用介绍视频充当实验。

软件回归是合同单位；完整采集流程是自主性单位；训练 seed 是策略变异单位；episode 是评测单位。
四者不能相互替代来放大结果规模。
