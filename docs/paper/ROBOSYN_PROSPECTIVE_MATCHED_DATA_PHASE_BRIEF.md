# RoboSyn 前瞻匹配数据研究：供 Main 自主设计的后续意图

本文件只是后续意图，不改变正在确认的旧研究，不增加预算，也不是已经冻结或启动的新实验。只有旧控制器完全退出、无在途作业，且正式继承原账本之后，才能用于新轨道。旧观察、失败、确认、模型费用与未知预留全部保留。

## 目标与已知限制

总体目标仍是在原生仿真 benchmark 上自主提高性能，数据获取是重点研究路线，而非所有优化的必经步骤。本阶段优先取得一个科学上可解释的数据学习对照；是否取得正收益由真实实验决定，不预设方法获胜。

允许使用的先验仅限旧研究的开发证据：新随机007得到6%／6%／8%，新策略诱导008得到0%／0%／0%；原始数据20k更新得到24%，与旧最高开发观察相同。六个数据观察没有符合原冻结配方的共同策略暖启动，也缺逐轨迹生产谱系，不能改写成公平方法结果。发布权重的旧开发参考为48%，不是本阶段已核验的基线。不要读取或使用旧确认阶段的输出、保留状态、日志或指标来做任何选择。

## 由 Main 决定的实验

1. **先建立可信共同起点。** 检查现成资源与可复用原生连接，选择并实际测量有证据的强策略；若已有可加载强参考，不要未经说明就用短训弱模型代替。冻结用于学习的共同初始模型身份，核验实际初始化，而非只看配置中的路径或视觉骨干。不同分支开始优化前应有可核验的相同初始策略证据。
2. **前瞻冻结设计。** Main 自选数据量、训练工作量、训练随机性、采样／混合／归一化、采集方式与评测协议。在看到新采集／学习结果之前冻结。预算允许时设计原数据等量续训、质量约束随机获取、学生失败／需求引导获取三个分支；做不齐的部分明确保留缺口，不把采集量或训练量不匹配解释为定向方法收益。
   若预留最终确认，必须在看到本阶段反馈前声明新的独立保留状态／种子，排除旧阶段已使用的开发与确认状态。旧确认集不可复用为本阶段未见测试集，也不得根据其分数调整本阶段设计。
3. **记录真实获取。** Data Agent 负责提出可执行方案、核对供给能力和质量条件。保存全部尝试与接受／拒绝、原生成功观察、监督来源、来源家族／场景条件、采集器版本、父策略实际身份和目标命中情况。区分观察到的字段、声明与未知。旧数据只能作为已存在资源，不能算本阶段新获取。
4. **按需改进采集器。** Main 可提出源代码依据的改进。研究期使用受审计的 `apply_workflow_candidate` 临时事务，另行核验并提交原生采集／数据准备，之后精确回退再做策略学习；不空跑训练来安装采集器。新 manifest 需与实际 producer／数据字节对应，不能事后补写旧成功证书。
5. **学习与计分身份闭合。** 实际 batch 消费、共同初始化、已完成更新、训练产物、真实加载、rollout 与指标逐项连接。对照按同一完整学习配方、实际学习量／预先选择的预算轴及固定原生裁判比较；采集成功或数据格式健康不是学生收益。
6. **保留失败与可解释边界。** 无法支持暖启动、监督质量、目标条件、资源或合法原生入口时，先做便宜的证据调查并交 Fix／Main 修连接。确认没有合法可行替代才报告边界；不能以安装或字段拒绝宣称仓库不可运行，也不能用不合规分数填完矩阵。

数值设置、具体 checkpoint、候选实现和研究顺序均由 Main 根据源码、能力与实时预算决定，操作者不代跑采集／训练／评测。若数据路线没有合理预期收益，可报告有效负结果并继续其他合法提分路线，但不能把其他路线的提升归因于数据方法。

## 资源、隔离与输出

- 继承同一个累计成本，不新发一份 GPU 额度：当前该 RoboSyn 研究总上限为30 GPU小时，包含原来同仓库外部试跑；已花费和未知项不清零。具体余额从权威账本读取，不引用本文件的静态估计。进一步GPU增加仍需明确授权。
- 旧研究的环境、公开源码、数据与开发策略只作为有 provenance 的显式只读资源／历史连接建议，不继承命令验收、实验批准或分数。不挂载整个旧研究输出，防止夹带确认内容。若使用操作者准备的热资源包，记录全部内容与介入，不称无人工冷接入。
- 只修改新轨道隔离源码，保护原仓库、已有数据、旧证据及密钥。模型不得接收密钥、checkpoint字节、原始轨迹或视频；可用公开源码、必要任务上下文、脱敏错误和聚合信息。
- 自主维护中文、面向读者的 RUN.md：展示当前问题、证据、实验对照表、成本、未完成项和系统自行产生的本地 demo／图表。没有实际观看图像的模型不能声称看过。
- 最小有效出口是一个前瞻、初始化与配方匹配、消费到评分可追溯的正或负对照。单次／单任务结果只作探索性证据，不自动称泛化、统计显著或SOTA；源代码合同测试不能替代此出口。
