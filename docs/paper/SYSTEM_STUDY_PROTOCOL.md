# 系统主实验：从原生仓库到自主指标优化

本协议承接总规划的 E1/E2，不替代当前 E0 开发，也不回写任何旧 run。矩阵仍是草案，任务未准入、资源与原生协议尚未冻结，不能据此启动18次正式研究或声称有18个结果。

## 比较什么

主问题是：相同合法资源和完整预算下，仿真适配能否提高自主研究的完成率、指标和资源效率？原始配方是校准控制，通用研究 Agent 与完整系统是主比较。数据获取是可选路线：通用 Agent 同样可使用允许的专家／数据／工具；不强迫离线或无权重控制器提交无关的数据消费证明。

系统重复的单位是一次独立启动的完整研究，不是候选、训练 seed 或评测 episode。最低三个研究重复；Agent 可在同一研究内自行选训练量与候选，所有尝试计入其成本。固定配方控制单列为独立原生重复，不声称进行了 Agent 研究。

| 轨道 | 输入和比较 | 不可混算 |
| --- | --- | --- |
| 原生仓库接入 | 未整理成统一模板的源码、目标、显式资源；比较通用工作流和完整系统 | 不能将模板内优化与仓库接入完成率混为一表 |
| 共同模板优化 | 相同任务、模型、工具、可改范围、视觉与预算；纳入 autoresearch-robotics 固定版本 | 原项目未承诺仓库适配时，不将该能力记作它失败 |
| 数据专项 | 专家／控制／消费成立时的随机、规则与 Agent 获取，必要时 Qt | 独立数据矩阵；不代表系统主实验全部动作 |

## 正式运行前必须补齐

1. 任务准入报告：实际资产、许可、环境、reset/step/render、策略或控制器和原生指标；记录已调试状态、可用干预及未知，不能根据正结果挑任务。
2. 强共同起点：核对官方配方、数据规模、学习量和部署语义；发布权重另作校准。低分先排除接线／欠训，不把安装通过当基线。
3. 冻结开发／最终协议：成功定义、样本数、随机流、初态证据、留出权限、最终策略选择与失败处理。每个系统／研究重复只确认它按开发协议选出的最终策略；不只确认全局最好的一次。
4. 公平资源：模型及可取得的版本信息、工具／技能／专家／视觉访问权、源码可改范围和完整成本。差异组件明确列出，不能给对照额外工具禁令制造优势。
5. 前瞻分配独立 output 和隔离 checkout；冻结代码／prompts／skills／工具身份。资源包来自小试与总体授权，不自动给每个单元重新分配24 GPU小时。隔离任务专用记忆，通用公开技能复用规则两边一致。

原生参数可由 Main 自主选择；协议保护的是评测裁判、合法训练域、总资源和可核查的实际执行，不预先规定必须改模型或采多少数据。

## 表格和统计单位

每个计划单元保留状态：未启动、运行、有效完成、资源边界、原生失败、框架失败、外部服务失败。未知／缺失不填零，也不从分母删除。

主表报告各任务的原始基线、每次研究最终开发／独立确认指标、完成数／计划数、首次可信分数时间、最佳值随完整资源变化和人工干预。每项测量沿用实际执行回执、加载身份、rollout与原生指标核验；发生训练才核验实际更新与数据，声称新增数据才追加来源／batch证据。

同任务按独立研究重复报告原始点、均值和离散度；episode不冒充独立研究样本。任务指标不同则分别列值，跨任务改进需事先定义尺度／权重。不在实验结束后选择最有利归一化。只有共同初态身份成立才能做配对比较。

## 当前工具能做什么

```bash
PYTHONPATH=autosim:. .venv/bin/python tools/system_study.py inspect \
  docs/paper/SYSTEM_EXPERIMENT_MATRIX.json
```

该工具校验系统／任务／研究重复及完整协议，列出全部计划分母和缺项；它不执行实验、不看留出、不挑 best，也不签发科学准入。完成原生准入、匹配协议及全部独立路径分配后，可将 phase 改为 formal 并执行前瞻封存：

```bash
PYTHONPATH=autosim:. .venv/bin/python tools/system_study.py freeze \
  <正式矩阵.json> --destination <新协议封存目录>
```

封存拒绝已初始化研究和重叠 output，不能追认当前 RoboSyn 开发轨迹为正式 trial。封存计划不授予费用，不证明资源可用，不把 formal_paper_eligible 置为 true。后续仍须接通逐研究结果导出、全部最终策略确认、成本／公平性审核与正式统计；当前工具只完成规划／覆盖／前瞻冻结层。
