## 1. 论文问题与范围

主张应是：**从策略开发失败中自主决定获取与保留的数据，在相同合法专家和数据/计算约束下，改善独立评测的数据效率**。
系统能安装环境、调用多个 Agent、画 RUN.md，不单独构成这篇论文的贡献。

第一阶段限定在资源可复现、可自动生成合法专家示范的机械臂模仿学习任务。
不把没有专家的 LIBERO 强行改成“可自动采集”；已有示范筛选可以作为另一条研究轨道，但不能与新增专家数据混算。
不将一仓库内换任务称为跨仓库泛化。没有可靠官方参考复现时只讨论相对本地配方的收益，不使用 SOTA 结论。

## 2. 最短执行路径

| 阶段 | 必须完成 | 退出门槛 | 不能绕过 |
| --- | --- | --- | --- |
| G0 前瞻接入 | 复用可用环境/资源，Main核验共同配方、原生输入与数据轴；旧成绩不继承 | 新轨道真实策略→rollout→指标、资源和消费身份可信 | 不删旧确认开放研究，不把环境hint当验收通过 |
| G1 数据小试 | 新专家轨迹、质量底线、转换、实际 batch、数据登记 | 新版本实际训练消费并独立计分，系统主动录制视频 | 文件存在/采集成功率不是策略收益 |
| G2 直接比较 | 一个任务先random_quality与agent_targeted；检验LLM价值加入rule_targeted | 两arm实际完成，来源/接受量/学习量/成本独立核验 | 暂不同时引入Qt和deployment，不先跑十种模型 |
| G3 版本冻结 | 根据 G0–G2 确定任务/数据量/学习量/初始化/评测/预算 | 预登记快照早于所有正式 run 初始化 | 不把有框架干预的 pilot 回溯转正 |
| G4 最小正式主表 | 先两任务、三训练 seed、五对照 | 全部单元含失败状态，独立评测与审核完整 | 不报最好 seed，不丢失败单元 |
| G5 扩展与机制 | 第二任务族、任务留出、独立 Agent 重复；资源够再仓库留出 | 冻结方法不改技能，任务/仓库留出分别汇报 | 仅变 seed 不是新任务；新训练 seed 不是独立 Agent 重复 |
| G6 投稿交付 | 主表、统计、图、真实视频、匿名代码/配置/证据索引 | 每项主张能指向准入实测；共同作者确认 | 草稿与软件测试不能代替实验结果 |

优先级：**修计分断边 > 新数据消费闭环 > 最小随机对照 > 多种子 > 泛化 > 更多工程功能**。
不要为了论文排版、补充 Agent 数量或非必要重构打断健康作业。

## 3. 基础矩阵与公平性

[获取矩阵草案](EXPERIMENT_MATRIX.json)提供四个候选任务、五方法、三个训练seed的60个单元；方法是fixed_official/fixed_continuation/random_quality/rule_targeted/agent_targeted。[Qt增量草案](EXPERIMENT_MATRIX_QT.json)另加fdas，共72个单元。二者bindings为空，原生未决字段保留null，不是新增预算或已冻结任务集。
任务名来自本地 RoboSyn 文档/配置，但资源可用、专家有效和耗时尚未逐任务实测；因此列表**尚未冻结**。
`assembly` / `rearrange` 是候选任务留出，不是已经完成的泛化，也不是仓库留出。

| 方法 ID | 数据/训练机会 | 所回答的问题 |
| --- | --- | --- |
| fixed_official | 共同初始官方数据、本地固定配方、三个真实独立训练 seed | 共同起点是否可靠；发布权重另做复现校准，不复制成三个训练 seed |
| fixed_continuation | 不新增数据；单独等总计算轨道给予相应续训机会 | 收益是否仅来自更多计算 |
| random_quality | 原生专家均匀/原生默认合法采样；共同质量底线 | 同量随机新数据的收益 |
| rule_targeted | 固定原生开发失败频率/覆盖规则＋共同Q0 | 不用LLM选择目标的控制 |
| agent_targeted | Agent开发失败解释、原生目标获取＋共同Q0 | 目标价值及与规则相比的推理价值 |
| targeted_quality | 冻结同一目标获取，仅共同Q0 | Qt消融的共同起点，不重复当独立获取方法 |
| fdas | 同样失败驱动获取，再做任务相关选择与官方数据混合 | 选择是否在目标获取之上带来收益 |

新campaign v2直接使用canonical方法、冻结预算轴/质量底线/共同因素；旧v1的unfiltered仍是无Qt但保留Q0，
targeted/random保持原义，不追溯重命名为已完成v2或规则结果。
`fixed_official` 中 official 修饰数据来源，不表示三个 seed 复用一个发布权重冒充独立训练。

三项研究必须分开：

- 等接受数据量：三个新增数据 arm 的新增合法独立 episode 数相同；初始权重、官方混合规则、学习量和评测相同。FDAS 为筛选多采的拒绝/额外尝试仍记成本。
- 等采集成本：预登记attempt或执行时间的一条主轴，报告实际产出/接受量和全部专家/转换成本，不混称等数量。
- 等总计算：固定数据续训、随机和 FDAS 使用预登记总资源包，采集/转换/筛选/训练/评测都记账，允许实际数据量不同。不能复用第一项结果后补称等计算。

学习量优先用实际 optimizer 更新及 samples/frames 曝光描述；相同 epochs 在数据量不同的情况下不是相同计算。
若训练器只支持 epochs，必须记录实际更新和曝光，并单独报告不同控制变量，不强称完全等算力。
初始化采用共同来源；恢复训练需 optimizer/调度器/normalization 的原生语义证据，不能只加载权重就叫续训。

## 4. 更有说服力的机制实验

完成直接比较后，按资源排序补充，不让消融挤占主表：

1. **目标与选择拆解**：第一阶段random_quality/rule_targeted/agent_targeted，仅共同Q0；第二阶段在同目标池上比较agent_targeted与fdas的Qt增量。targeted_quality作为旧标签保留，不把与agent_targeted相同的处理重复计算为独立方法。
2. **规则型失败定向对照**：在相同已验证可控条件空间中，根据失败频率/覆盖缺口选目标，不用 LLM 解释。用于检验收益来自自主推理还是简单分布重采样；实现/计算成本要计入，未实现不引用其名字作已完成对照。
3. **失败信息消融**：不给 Data 当前失败诊断，仅给仓库能力、同预算与官方数据；其他角色/模型/权限相同。不要用错误标签制造有害训练数据。
4. **数据量曲线**：选代表任务，在预登记的三个增量上评测；各点独立训练或明确同一续训链，不能把同一模型多次评测当独立样本。
5. **失效与覆盖**：失败目标的支持率、专家尝试→成功→接受→去重→实际消费漏斗；图中的分母与拒绝理由均来自原生计数。
6. **原分布保持**：检查新数据是否提高目标条件却损害原分布任务，报告加权规则和遗忘，不只挑目标切片。
7. **端到端自主性**：至少三次完整获取/选择流程的独立启动，测完成率、首次可信分数时间、框架修复/人工干预、费用。不能重用同一采集数据把三个训练 seed 叫三次自主流程。

DataMIL 可作为实际数据选择对照，但其额外模型训练/目标数据条件必须满足并计成本；
RESample 需要对应恢复/探索能力，不能将只会 reset 的专家包装成该方法。
已有相关工作的机制差异应实测说明，见 [DataMIL](https://arxiv.org/abs/2505.09603)、
[RESample](https://arxiv.org/abs/2510.17640)、[MimicGen](https://arxiv.org/abs/2310.17596)。

## 5. 本轮真实阻塞怎样转成实验前校准

旧试点停止的关键科学问题不是“换 seed 即独立”：原生 evaluator 将 episode seed 送入 reset，
但 SDK 与任务逻辑可能分别消费 Torch、NumPy、Python random。必须沿**当前任务实际启用的配置**追踪，
不能仅凭在整个 SDK 找到一个未设种子的函数就断言它一定影响本任务，也不能只引用函数定义就证明它被调用。

校准需要系统 Init/Fix 在隔离 checkout、正式冻结前完成：

- 核验 evaluator→reset→实际采样模块的完整路由；如随机源未接通，在不改任务分布、成功条件和指标的前提下补连接，并记录源码差异。
- 同种子重复初始化应得到相同的**任务相关初态**，不同保留流的初始化应经实际哈希/状态证据检验分离；不要把完整图像噪声/随机光照哈希当机械状态差异的替代。
- 正式评测保留初态身份，使随机、定向和基线在共同初态上比较；如确实不能配对，使用非配对统计并披露，不捏造配对。
- 若必须构造初始化 bank，它是所有方法共同的评测设施，不是只给 FDAS 的优势；bank 在搜索前生成/冻结，不因看到结果改内容。

这是评测可复现性校准，不是修改学习策略来提高分数。操作者直接修改校准适配器或路线时必须记录干预；
开发阶段可以修，正式阶段不原地改已冻结版本。当前运行由 Main 自己调查和决定下一步。

本轮已发现一项先修设施问题：历史试点的只读目录查询过早冻结了保护源，
后来的评测见证插桩触发 `protocol_changed`，而旧 measurement 将其误报为缺少加载日志。
当前修复将新运行的持久冻结推迟到实际请求测量/执行，封存执行前原因并交给 Fix；
不删除历史冻结、不改旧测量、不将失败计成零分。旧协议若不能在保持其身份的情况下恢复，
必须显式另立开发版本并保留失败和全部成本；不通过偷偷重写冻结证明恢复成功。
正式矩阵必须在完成共同校准之后、任何正式 trial 初始化之前冻结。

## 6. 单卡可行性与预算

本机RTX5090。2026-10-12前瞻轨道转移时GPU累计约9.405/24h，模型80美元总上限、安全余额约12.803美元，
旧消耗/预留和墙钟起点全保留；后续数值看当前账本，不是给每个未来单元重开24h。

不要立即启动60或72个计划单元。先做两任务的获取对照（独立训练基线时30单元），真实成本和方法效果允许时再加Qt、任务/后端与自主流程重复。G2后基于实际时间估算：

`GPU总量 = 共享初始化 + Σ获取(含失败) + Σ转换/筛选GPU段 + Σ训练 + Σ评测 + 失败余量`

以实际完成学习量估算训练速度，不用环境准备的窗口当训练时间。
所有新增仓库/正式研究预算由操作者显式分配，Resource 在包内调整局部机会；未知模型用量继续保守保留。
计划超预算时优先从四任务减为两任务，保留随机直接对照和三个 seed；不要改成大量单 seed 亮点。
不得通过开很多 task run 绕过用户指定的每仓库 GPU 总预算。

## 7. 冻结、汇总与准入工具

`tools/data_study.py` 已提供以下能力，不启动 GPU 或模型调用：

- 生成完整笛卡尔矩阵，单独标记训练 seed 和 Agent 重复；待执行不填零。
- 显式绑定 measurement/campaign，原生 receipt 和数据消费复验；同一测量不得对应两个方法或种子。
- 按每个 Agent 重复分别汇总训练 seed，保留完整性分母；不合并不同指标单位、不挑 best seed。
- 正式协议仅可在全部正式输出尚未初始化时冻结；身份快照覆盖代码/提示/技能和工具。当前源码与冻结快照不匹配会显示。
- 正式获取设计可只包含获取处理，不再被强制添加fdas；agent_targeted必须有random_quality和rule_targeted，未定协议仍不能冻结。旧random/FDAS合同兼容，不替旧数据换标签。
- 已预分配但未初始化的输出显示pending而非实验失败；绑定目录的symlink父路径在冻结前拒绝。计划问题、Qt是否纳入和未绑定分母直接输出，不推断已经完成科学对照。
- 内容寻址 JSON/中文 MD，去重 whole-run 费用；不能平均分摊成各 arm 成本。

```bash
PYTHONPATH=autosim:. .venv/bin/python tools/data_study.py inspect \
  docs/paper/EXPERIMENT_MATRIX.json \
  autoresearch_runs/cvpr2027_study_20261010/reports

# 将本地完整填好的协议设为 formal，绑定未初始化的输出后才允许：
PYTHONPATH=autosim:. .venv/bin/python tools/data_study.py freeze \
  /absolute/path/to/finalized_protocol.json /absolute/path/to/preregistration
```

**工具不自动批准论文主表。** 还需要每个 arm 的独立留出分数（现有一次 best-confirmation 不覆盖所有 arm）、
原生 seed/实际工作量审核、方法公平性审核、逐 arm 成本归属及匿名审计。
当前每行明确 `formal_paper_eligible=false`，防止把计划冻结或开发 receipt 一致自动当科学认证。
未来正式准入必须另外实施并验收，不能把这个只读矩阵工具叫做完成了正式评测平台。

## 8. 表图与写作交付

主表：每任务×方法成功率、训练 seed mean/std、完整性分母；episode 区间另表，不能伪装成训练 seed CI。
