# 失败驱动数据研究：第一个真实闭环试点

这是开发可行性试点，不是论文主实验，也不要求无限开放式科研。目标是在既有合法资源上，由系统自主完成一次新增数据→筛选→实际训练消费→同协议计分。优先检验原生自动专家/生成器。不要人工代选学习参数、改评测、用测试失败采数或以零动作复制轨迹凑数。

准备时复用已存在且经消费者验证的环境与只读资源；必须调查原生 collect/prepare_data/loader/数据轴，在冻结前连接。若现有评测只给成功率，应在冻结前连接不改变指标/成功判据的开发诊断输出，记录原生可观察的阶段/合法场景/偏离信息，支持后续目标判断；不是伪造失败标签或改评测初态。专家不依赖当前学习策略低分。发现真实依赖错误用稳定证据交 Fix，修后复验，不重复全量安装或重复整段训练验收。

取得真实 baseline 后请 Data 调查开发失败。区分观察和原因假设：仅低成功率时先取得可区分的诊断，不编造阶段标签。提出一个原生可控的训练场景目标。先做少量专家采集验证成功、接受、完整轨迹、动作标签和实际 loader batch。原始数据保留，筛选单独输出并登记身份、父版本和 profile；不得直接把开发评测轨迹加到训练。

登记 campaign，预先声明 targeted/random 等可用 episode 比较，数量由产出率、训练数据基数和剩余预算决定。共同质量底线、专家、合法域、官方混合、初始权重、训练完成工作量和评测固定；失败收集与转换全部计成本。试点可先一个训练 seed，不能作为统计充分主表。

训练必须显式消费登记的数据版本，并提供实际 samples/batches/source 读取证据；加载对应权重并运行冻结开发评测，再记录 arm。视频通过系统自己的 demo 接口主动采集并展示；中文 RUN.md 说明原因、目标/随机采到多少、实际消费及指标。未执行的对照显示待执行，不填零。

如供给链证明无法自动采集，给出当前缺失能力/资源及已尝试证据，允许合法已有数据筛选，但不得称新增采集闭环成功。保持原 baseline；收益为负也是结果。请 Resource 安排长作业/局部时间预算并守总额，保留训练/评测资源，不把一次入口窗口耗尽当成环境坏了。
