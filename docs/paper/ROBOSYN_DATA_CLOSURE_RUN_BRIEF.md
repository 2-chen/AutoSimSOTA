# RoboSyn 前瞻数据闭环开发轨道

用户于2026-10-12授权继承原研究账本并追加$10模型和24小时累计墙钟；GPU仍为原24小时总上限。保留旧run、全部失败、旧24/100与32/100开发成绩、费用和预留，不删除旧确认记录，不回溯改成正式数据trial。当前模型统一deepseek-flash。这是开发轨道，人工框架修复需单列，不伪称冻结零干预研究。

## 本轨道优先完成什么

完成至少一条真实的“合法专家数据→质量/可逆选择→实际训练batch/来源曝光→新策略→原生开发评测”链路，再做可完成的随机/失败定向直接对照。主Agent选择任务内目标、原生控制、接受量、种子、策略与训练工作量；Data持续调查获取/筛选/消费者，Resource依据实际吞吐安排完整链路预算。不要由操作者预填press_depth目标或固定采集/训练数。

先复用已经可运行的依赖基座、源修复与只读资产，用当前源码/消费者复验，不重建整个仿真栈。源仓库不能修改。已发布权重参考、旧本地训练和旧部署优化是历史信息，不是本轨道的新baseline、数据arm或正式SOTA。

源码bootstrap中包含上一Agent的部署YAML研究设置，不全是环境兼容修复。请识别研究变化、核验本轨道共同配方并重新建立真实baseline；不能把复用源码自动称作原发布配置或把旧成绩晋升本轨道结果。

## 执行与停止规则

初始化时先建立collect/prepare_data/train/evaluate及真实数据轴、可控训练条件路由、转换与batch小试能力，再冻结评测。首个开发评测前核验真实reset/初态/随机源及独立保留条件；确认seed不是只换标签。任何held-out反馈不回流数据目标。

保留共同有效性底线Q0；从开发失败提出可证伪目标，先验证控制小试的真实条件/单位与专家动作。只有结果可观察、不能直接控制时允许随机池后筛选，并报告额外采集/拒绝成本；没有可用恢复专家就不声称DAgger/中途恢复。覆盖无变化、低产出、消费不成立或下游无收益时，诊断/改目标/回退，而非无界扩量。

在新干预前登记schema_version=2 campaign；先按剩余资源选择可完成的随机/Agent目标比较与共同配方，检验LLM价值时加入有真实开发分层计数的rule_targeted对照，必要时加fixed_continuation。数量/目标/学习量由系统选择并冻结，不倒改为观察到的产出。等采集成本、等接受量、等资源包分别解释；旧数据作为共同起点不能计为新增。

小试后用实际产出率、CPU/GPU吞吐、存储、处理、训练/评测及模型成本再决定下一批。长任务通过现有原生job提交/延期/取消；不因一个短本地窗口超时就重做所有安装/训练。部分采集失败先检查完整产物并登记父失败，再修原操作；训练产物必须实际加载后计分。所有失败成本保留，不重置账本。

已声明数据arm须到消费/开发计分，或通过有正面证据的独立unsupported/budget_limited边界，才进入confirm_best；不要用参数优化分数绕过未执行的数据研究。能力不足先穷尽合法小试/修复/筛选，不把可修错误当永久不支持。未知预留不得凭进程退出释放，总量之外不能自行加预算。
