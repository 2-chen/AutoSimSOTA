# 采集与数据准备源码事务

研究已开始后，普通 `research_task` 仍不能任意编辑源码。策略候选继续走训练／评测事务；采集器、转换器和数据准备代码则有独立的受审计通路，避免为安装一个采集补丁空跑训练。

Main 选择已 `cleared` 的精确 code idea，通过 `apply_workflow_candidate(idea_label, target_stage, reason)` 请求临时应用。目标限于已声明的 `collect`、`prepare_data`、`convert` 或 `preprocess`。独立只读 Supervisor 检查真实入口、全部改动后的代码、学生训练与原生评测／冻结协议及旧数据是否保持；不确定时不应用。这个操作只改隔离 checkout 中清单内的已有源码，不启动作业，不消耗研究轮数，不登记质量或分数。

应用前封存原文、补丁、请求和审查，先让旧命令验收失效。Main 再选择命令蓝图或推导入口，完成新源码上的原生验收，另行提交采集／数据准备作业。新数据沿既有 producer、检查、不可变登记与消费核验进入后续研究；补丁回执本身不能充当原生生产或计分证据。

采集／准备结束后，必须先调用 `restore_workflow_candidate(patch_id, reason)`，才能训练、评测或确认策略。回退只恢复仍精确匹配该事务前／后图像的文件，不覆盖其他修改；新数据及其真实生产回执保留。重新验收训练／评测入口时，保留冻结的函数源码和协议，可用历史蓝图恢复连接，不重测或重写原基线。

## 恢复与边界

- `workflow_source_patches` 显示事务和当前限制。`read_evidence(workflow-patch:<ID>)` 可分页读取脱敏请求及独立审查，优先展示决定；不提供回退原文或任意路径读取。
- 审查中断尚未写源码时，可在原文身份仍一致的条件下取消；应用／回退中断后，未完成记录会阻止其他写入与原生执行，直到精确恢复。活动作业、GPU 租约或确认尝试阻止源码迁移。
- 不能编辑源仓库、只读资源、外部 SDK、系统代码、旧轨迹或计分记录；不能借此扩预算、改学生训练／评测合同或把旧未知质量补写成通过。
- 审查是有界源码与语义审核，不是完整导入图或程序等价性的形式化证明。实际作业、数据质量、策略加载、rollout 与指标身份仍各自验收。

2026-10-19：CPU 合同及关键回归已通过，真实 RoboSyn 研究已恢复。Main 是否自主使用此通路、是否产生可信的新 manifest 及有效数据收益，仍须真实轨迹证明；软件入口落地不等于这些实验已经完成。
