# Prompt 与 Skill 维护规范

## 分工和维护位置

本系统采用一个 Scheduler 主导研究、按需委派角色的结构，不要求每个角色常驻一个模型进程。提示词负责表达目标与职责；真实执行权限、操作 schema、冻结评测和总预算由执行器验证，不能用提示词或技能绕过。

| 层 | 维护位置 | 内容 | 不放什么 |
| --- | --- | --- | --- |
| 共用研究原则 | `autosim/autosim/prompts/core.md` | 用户目标、角色关系、事实/假设区别、证据与输出约束 | 仓库名称分支、参数配方、运行日志 |
| 角色任务 | `prompts/scheduler.md`、`specialist.md`、`monitor.md`、`fix.md`、`ideator*.md`、`recorder.md` | 本角色决策范围、必要判断、精确响应格式 | 另一角色的工具权限、无关操作教程 |
| 操作专属合同 | `prompts/environment-*.md`、`execution-*.md`、`objective-*.md` 等 | 该操作需要的字段、源码判断、失败与输出规则 | 强迫所有操作走同一研究路线 |
| 运行能力 | `research/agent_roles.py` 与执行器 allowlist | 可用工具、只读/编辑/CPU 诊断边界 | 根据 skill 的建议扩权 |
| 方法技能 | `skills/<name>/SKILL.md` 和 `references/` | 触发问题、前提、方法选择、验证与不适用情况 | 当前 run 的候选结果和全部故障历史 |
| 技能索引合同 | `skills/manifest.yaml` | ID、版本、适用范围、证据等级、I/O、权限/资源说明 | 完整方法正文或大型文献报告 |
| Idea / 运行记忆 | 每个 run 的 Idea 库、计划与封存记录 | 仓库特定假设、结果、未解问题与证据引用 | 冒充通用定律或覆盖真实评分 |

## Prompt 编排

静态全局 SYSTEM 提示词共 **29 个任务模板**，统一放在 `prompts/`，另有 `core` 和 `runtime-tools` 两个共享模板。原 Python 常量名仍保留，通过 `research/prompt_library.py` 加载；调用方和操作解析器不变。

`candidate-execution-review` 在付费候选执行前让无工具 Supervisor 对照当前 stage、原生包装脚本及修改内容，检查因果连接与明显矛盾；标准研究轮次和带 idea 的长期训练都使用同一审核。按源码字节、候选及提示词身份缓存，源码/提示词变化后重审。不确定时交回 Main 补证据，不按仓库名称判决，也不把源码上的可能连接当成实际加载或指标证明。

接口形状/单位/时序修改的机制如果依赖未提供的安装库语义，必须先做原生 CPU 合同探针，不以完整训练后首个推理报错替代廉价检查。审核可读取当前环境身份匹配、哈希完整、成功且无 GPU 的最近三份封存诊断；切换环境或证据变化会改变缓存身份，截取日志明确标不完整。诊断文本不是指标或所有声明的真实性证明。格式/引用校验失败最多一次无工具反馈重试，不放宽精确引用约束。

主要角色模板由加载器前置一次 core；操作专属模板保留独立精确合同，避免所有短操作重复增加通用段落。工具说明按能力附加：Recorder 无任何工具提示；只读角色不能得到编辑或命令执行建议；Init/Fix 才附环境修复交接说明。调用方的 JSON/代码 schema 优先于泛泛的“返回 handoff”，不存在同时要求两个输出格式的模板。

Recorder 的字段、正文 1–700 字和每段 1–6 引用必须与执行器一致。引用来自显式 `allowed_evidence_ids` 顶层键，不使用材料内部的 UUID/路径。最多一次原剩余窗口内的格式反馈，汇总各段错误后仍整篇严格验证；不新增总预算、不把标识符编号当性能值、不丢掉数值符号或其他性能提及的验证。已有原生执行/正式测量与当前动作优先于旧安装历史/模型计划；缺可选投影不推翻真实计分，官方复现缺口也不等于环境不可运行。独立验收与当前在线系统行为分开记录。

Scheduler 模板分为全局职责、环境恢复、基线/提分、数据决策、操作合同、方法选择和响应合同。详细接口约束在相应操作时适用，不构成强制流水线。保留既有恢复/身份/计分合同；这轮没有把 Main 改成一个只会选关键词的路由器，也没有删掉当前大模板的全部历史接口细节。

动态 schema、原生参数、当前预算、故障 ID、资源绑定和测量放在请求 payload；可引用细节由工具按需读取。动态拼接的局部操作/审核提示仍留在相应代码中，不谎称所有调用都只使用一个固定模板。

原有 onboard_task_prompt / ideas_task_prompt / optimize_task_prompt 三个模板没有当前代码调用方，保留历史内容并标注停用；不进入 active registry。其 play_once、成功率默认、固定 idea 配额、结构改造优先与手工评分流程不作为当前合同。加载器拒绝这些名称，不删除原文件或假设外部用户没有历史用途。

模板名为代码 allowlist，不能让模型传任意路径加载 system prompt。加载器拒绝未知名称、软链接越界、空模板及超大文件；内容在进程中缓存形成稳定前缀。修改模板后应受控刷新/重启运行器，不对运行中的研究静默热更新。全部模板内容纳入 controller identity，版本变化使历史失败需要重新核验，不自动宣布已修复。

`decision_only` 实际关闭全部工具时，附加角色说明也同步收缩为仅基于快照决策，不再提示执行原生探针或公共检索。普通只读调查与无工具决策不是同一种能力；schema 与权限按本次实际调用解释。

Scheduler 使用 `.format(operations=...)`：只允许现有 `{operations}` 插槽；所有示例 JSON 花括号必须双写。其他模板不自动替换花括号。模板文件及技能/参考资料已声明 package-data，打包部署不再只带 Python。

## Skill 格式与渐进加载

### 角色协作边界

| 角色 | 本轮应交付什么 | 不越过什么 |
| --- | --- | --- |
| Scheduler / Main | 全局计划、证据判断、角色任务、下一合法实验与停止理由 | 不自改权威分数/总预算/冻结协议 |
| Resource | 原生数据动作来源、已有/官方资源、生产→转换→loader 的源码连接与缺口 | 发现可行路线不等于执行成功 |
| Objective | 可核验 rubric、指标/方向、协议与红线 | 不猜指标、范围或改评测 |
| Init | 复用环境、最小消费者验收、可执行阶段/数据接口、学习工作单位 | 环境验收不索要未来权重，不把 smoke 当正式基线 |
| Monitor | 真实进展、停滞、当前资源/预算及恢复建议 | 不自行选候选/计分或宣布修复 |
| Fix | 读取稳定错误证据、最小修复、修后原能力复验提案 | 不通过 CPU 工具写活跃 prefix，不以弱探针取代原操作 |
| Ideator | 有前提、因果预期、风险与源码证据的可执行候选 | 不猜 patch preimage，不用留出反馈指导数据 |
| Supervisor | 独立审核协议、真实加载/消费、结果有效性 | 不修改候选来让审核通过 |
| Recorder | 基于开发证据的中文解释、表图与 demo 观察请求 | 无工具/留出访问，不直接制作仿真或宣称未测收益 |

同一角色在 investigation、read_only、decision_only 回合的工具可能不同；以实际 allowlist 为准，不从角色名推断权限。技能只扩展方法知识，不增加角色数量或权限。

### 发现与选读

内置技能 header 保持简短，至少 `name`、`description`；已有支持的 UI metadata 可保留。描述写清“何时用、解决什么”，不要列满领域术语。适用条件、证据局限和验证方式写在正文；较长 schema/文献/分模式程序放 references，并明确何时读，不递归展开全部引用。

内置 skill 的 scope/confidence/evidence 和版本合同以 manifest 为维护位置，加载器合并 name/description。外部或蒸馏技能没有 manifest，必须自身携带完整版本和检索合同。兼容旧 header，但显式 scope 冲突会诊断并拒绝，不能把 benchmark 范围降成 general；选读时再核验身份/合同未变。格式错误的技能进入诊断，不直接终止研究。

方法建议不等于硬规则。`general` 只表示跨仓库可考虑，不表示结论已经普遍验证；`benchmark:<name>` / `task:<name>` 限制检索范围，拼错不能默认为通用。原 RoboSyn 历史数字仍局限于对应 benchmark，并保留未重审的证据等级。没有证据等级默认 unspecified，不臆补可信度。

Main 路径保持：短目录 → Agent 选 0–3 个 ID 并说明理由 → 读取所选正文 → 评估前提/失效条件 → 当前实验验证。关键词仅标记推荐，不排除其他适用条目、不替 Agent 决策、不增加权限。缓存记录 ID/版本/body hash/理由；实际研究里程碑和正文变化触发重选，普通心跳不重读整库。参考资料不会自动注入，需按当前问题主动读。

兼容接口 `skills_reference` 仍为旧调用提供关键词推荐正文；不能把它的旧行为说成所有角色均已采用显式选择。`discover()` 用于维护/检查，可读取全部正文；正常 Main 目录调用不读全部正文。

## 修改与验收

1. 先分类：权限/接口 bug 修执行器及 schema；可复用方法修 skill；仓库参数放 Idea；当前失败保留封存证据。不向全局 prompt 不断追加事故日志。
2. 不改变原 ID。正文或合同有语义变化时更新 manifest 版本；纯元数据搬家不虚构新实验。历史证据和 benchmark scope 不丢失。
3. 保持所选内容自洽；不通过技能授权下载、上传、删除或改变评测。新方法必须给当前可验证前提，不保证 SOTA，不设置全仓库统一数据量/小时数。
4. 执行技能标准校验、目录/范围/按需加载、角色工具、模板格式、controller freshness、包资源和相关操作测试；修改全局编排后跑完整 CPU 回归。文字测试只证明接口和边界，真实自主行为仍需端到端仿真验收。

常用检查：

```bash
PYTHONPATH=autosim .venv/bin/python -m pytest -q autosim/tests/test_prompt_skill_contracts.py autosim/tests/test_skill_library_guide.py
PYTHONPATH=autosim .venv/bin/python -m pytest -q autosim/tests
```

本轮整理不启动实验、不增加预算、不改源 benchmark，不把格式整理当作自主提分验证。
