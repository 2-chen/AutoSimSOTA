# LIBERO 停止原因与数据优先刷分改造

## 最新：锚点安装失败与三项通用恢复修复（2026-10-01）

`robosyn_recovery_anchor_20260930_v1` 已停止，下面的“正在调查/已启动”为历史记录。该 run 完成部分真实安装，但没有通过环境探针、没有采集/训练/评测；约 76 分钟、模型约 $1.04、GPU 0，不能解释为 GPU 或总预算耗尽。

本轮修复执行路径被展示脱敏破坏、错误安装命令必须重放、原生安装失败没进入外层事务三个通用接口：

1. 源码配置中的 run-local 相对依赖先映射到稳定别名，模型只见别名与 run-relative 目标；执行侧本地还原后校验。真实 RoboSyn manifest 只读回放将 `../..` 映射到隔离 checkout、`../../../EmbodiChain` 映射到 run/EmbodiChain；不写该仓库的专用规则。脱敏展示保持启用，`[OUTSIDE_PATH]` 不再获准执行，未知/越界/符号链接逃逸拒绝。别名仅表达路径，不证明包存在或可消费。
2. 修复前置条件时仍复验有效原操作；错误安装操作允许 `replace_operation`，要求失败证据 ID、同一能力说明、安全源码引用和独立只读 Objective 审核，引用必须与源码相符。批准后退役旧命令，不追加错误 pip 操作；未批准不能退役。所有原生能力探针保留，不允许改指标/评测、跳依赖或装 stub。审核不是执行成功。
3. `checkpoint failure` 标记 `native_install/environment_executor` 并传递稳定失败 ID、操作身份和回执；修复队列属于安装器，主 Agent 负责继续其能力复验，不重复派源码 Fix。相同操作有界复验失败保留“未解除，需新证据”；前置命令成功不能抹去原故障，新操作的新失败可形成新事务，完成环境核验后才解除。

新增安装专项 11 个，含真实配置只读回放和 cooperative 安装队列/外层 checkpoint 合同；完整 CPU 回归 1384 passed、1 skipped（194.73 秒），相关集合 163 passed、1 skipped，最后补充修改后 68 passed、1 skipped。编译、空白检查通过。本轮没有真实 API/GPU实验，不改旧 run 事实或源仓库，未自动重启；尚不能据此宣称安装恢复或 SOTA 已实测通过。

## 最新：RoboSyn 接入失败后的接口修复

`robosyn_transportfix_20260930_v1` 已停止，不再是活跃验收 run。运行约 45 分钟，64 个模型回合结算约 $0.62，未知预留 0，GPU 消耗 0；此前计费网关修复正常，但仍未完成原生实验。

本次故障分别是：环境方案混入 train 启动命令并虚构 dataset 路径；方案解析器把解释中的 `{repo}` 当作 JSON 开头；异步调查不支持实际文件范围，复制 303.8 MiB 输入后触发 64 MiB 上限；源码 Fix 只得到字符串错误，不具备修复框架解析器的权限。

已实现：

1. 方案解析采用独立 JSON 块/完整对象扫描，忽略解释中的占位符；多个对象明确拒绝，不猜选、不执行 Python 字典。
2. 异步任务新增 `source_paths`（最多 64 个相对文件/目录）。执行器实际按该范围复制，复制前检查安全路径和总大小；manifest 记录范围和字节数。缩小 task prose 不再冒充缩小快照。越界、空选择、未找到路径仍拒绝。
3. 环境规划收到明确资源短目录和 `bound_resource_N` 别名，不暴露资源宿主路径；声明路径通过实际只读绑定检查，而非仅检查空挂载占位。数据存在仍只是元数据，必须原生消费探针验证。
4. 失败封存被拒绝的方案、全部校验错误及原生未开始的事实，经稳定 ID 交回主 Agent；下一次规划自动收到上次失败的证据入口、错误和有界提案摘要，不依赖主 Agent 记住或手动复述。完整提案按需读取，不整份灌入上下文。
5. `framework_plan` / `environment_planner` 区分方案失败和源码故障。方案失败不再触发源码 Fix 扫全仓库；主 Agent 被指导修正环境提案并复验原操作。仍禁止安装阶段偷跑训练/采集/评测。
6. RUN 增加中文方案失败说明和完整证据入口；不把校验拒绝描述成仿真不支持。

专项回归 15 passed，包含只读回放该 run 的真实源码与资源合同；选定范围的实际快照由 303.8 MiB 缩至 16.8 MiB、98 个文件。完整 CPU 回归 1363 passed、1 skipped；最后补充跨次规划失败证据传递后，相关测试再次 50 passed，文件空白检查通过。没有改旧 run、源 RoboSyn 或手写实验配置。本轮未重启长时实验，也没有新 baseline、采集轨迹或 SOTA 结果。

## 后续 v2 故障修复与 RoboSyn 验收（2026-09-30）

LIBERO `datafirst_v2` 确实开始安装，但环境克隆因后台服务 PATH 缺少 Conda 失败。之后模型请求用量被标为未知，本地网关直接拒绝同回合后续调用；11 个未知回合各冻结 $4，尽管请求回执中的未知上界合计约 $1.43。Scheduler/Fix/Monitor/Recorder 共用网关，恢复调用也失败，最终框架退出。这不是训练或 rollout 崩溃。首次未知请求的原始上游原因未封存，不能断言是 DeepSeek 宕机。

此次修复：

- 安装器先解析明确配置、PATH 与常见安装目录，执行绝对路径；新的宿主服务同时保留 Node、Conda 与系统工具 PATH。
- 未知用量保留每请求已批准的费用上界，并参与后续请求准入计算，不直接锁死网关。总预算、请求数量上限和不支持的模型检查仍有效。
- 网关保存安全的 HTTP 状态、异常类型、阶段及用量失效原因；不记录密钥、原始请求或响应内容。流式响应未结束时不把初始输入 usage 当完整费用。

- 模型通信故障与额度拒绝分开归类；Scheduler 通信失败有界重试，不再为同一失败额外调用 Monitor/Fix，三次重试后保留具体证据停止。

## 结论

本次 `libero_agentloop_20260930_v1` 没有完成原生实验，不能把停止归因于 LIBERO 训练失败、5090 不支持或数据采集不可行。它主要卡在框架的环境规划阶段：配置的 900 秒回合被内部调用改成 300 秒；失败没有把模型执行过程可靠地交给 Fix，导致重复调查和无依据的配置修补。

当前目标重新明确为：**在固定、合法的 benchmark 协议下自动提高指标**。Agent 仍负责推理与适配，但调研、技能和子任务应服务于下一项能运行的操作，而不是先完成开放式科研。

## 这次实际发生了什么

证据目录：`autoresearch_runs/libero_agentloop_20260930_v1/`。主要依据是 `preparation_derived.json`、`agent/runtime_spec.json`、模型事件、进程回执与预算账本。

| 观察 | 意义 |
| --- | --- |
| 运行约 52 分钟，最终 `adaptation_unresolved` | 准备阶段主动停止，不是正式评测得分退步 |
| 原生实验未完成、GPU 计费为 0 | 没有证明安装、训练或 rollout 失败 |
| 配置模型 timeout 900 秒，环境规划实际多次 300 秒超时 | 框架局部上限覆盖了用户配置 |
| 一个回合在截止前已经输出方案及 session result，随后被记作超时 | 逐事件刷新报告及输出排空存在边界问题；不能直接采信未完成回合的方案 |
| 资源挂载占位目录被普通读文件工具看到为空 | 缺少显式资源元数据检查入口；空占位不能证明资源不存在 |
| 早期只读任务要求尚未生成的 `derived_stages.json` | 依赖顺序错误，调查本身不应要求已经得到可执行命令 |
| demo 的目录引用被称为“逃逸 checkout” | 检查混淆目录与不安全路径；而且原生上下文未发布时不应提出实际仿真预览 |

本次不是总预算耗尽：GPU 额度基本未动用，模型已结算约 $0.66，另有约 $8 未知用量预留；预留不是已确认支出。具体金额以原账本为准，不追溯重写。

旧 RoboSyn 成功依靠专用管线把采集、数据转换、训练和评测接好了。当前通用化把这些连接拆开后，增加了准备依赖和模型回合，却没有保持同等的端到端验收。因此，旧专用闭环通过不能证明新通用框架也通过；也不能据此承诺当前 LIBERO 已达到 SOTA。

## 已实施的修复

1. 环境规划、恢复、重考虑和诊断尊重当前 Agent 配置的回合时限；仍受总预算约束。不无限延长活跃进程。
2. 进程已经退出时先排空输出，避免缓慢报告回调导致伪超时；活跃进程超过截止仍中止。Agent 事件继续逐条持久化，RUN 投影节流，结束时强制刷新。
3. 模型回合失败单独封存：配置时限、实际过程、最近工具事件、未采纳响应、稳定 evidence ID。明确“原生操作尚未被证明失败”，指导 Fix 先修运行器问题，不猜测改 benchmark。
4. 增加只读 `inspect_workspace_resources` 工具，按明确授权的资源目标检查实际目录名称、类型和大小。拒绝任意宿主路径及链接遍历，不读取数据文件内容；调查角色也可使用。
5. 没有派生命令时允许建立早期源码身份；取消环境准备必须先有全局科研计划的门槛。正式实验、计分及协议监督仍需完整合同。
6. demo 接受 checkout 内真实目录引用，区分缺失与逃逸；原生上下文尚未发布时不提供环境录像操作。
7. 主 Agent 与 Init 提示改为执行优先、数据优先；新增按需技能，而不是按仓库名称选择固定采集脚本。
8. 可记录 `data_strategy`：路线、选择理由、针对哪些失败、生产者到 loader 的连接、证据及下一项小探针。它只是 Agent 计划，不授予执行权限、不证明数据已生成。
9. RUN 增加中文停止原因、模型回合故障说明和针对性数据计划表。计划、原生执行、成功录像和正式分数仍分别展示。

## 数据能力：先知道谁能产生正确动作

“有仿真器”不等于“有自动专家”。需要分别核查专家/规划器、控制接口、成功判定、保存字段、转换器和训练 loader。

| 路线 | 前提 | 适用边界 |
| --- | --- | --- |
| 原生专家或运动规划器 | 已有可运行任务专家、机器人配置与成功判断 | 优先采样合法训练场景；仍须验证控制器和数据格式 |
| 已有策略成功过滤 | 兼容的权重/观测/动作接口，并已有一定成功率 | 只保留成功且合格轨迹；零成功率不能凭空自举 |
| 演示轨迹适配 | 源演示、物体位姿、子任务切分及对应环境接口 | 可以扩大状态覆盖，但不是任意仓库通用专家 |
| 专家纠错 / DAgger | 能在学习器访问的状态上查询正确动作 | 普通失败轨迹或成功筛选不等于 DAgger |
| 人工遥操作 | 人类操作设备/交互 | 是支持采集，不是无人值守自动采集 |
| 公开兼容数据或权重 | 可下载、许可符合协议、版本与任务匹配 | 先核验来源及 loader；下载成功不等于模型实际使用 |

RoboTwin 官方提供专家规划采集及预采集数据说明，但版本、任务配置、机器人和转换路径须以输入仓库为准。[官方采集文档](https://robotwin-platform.github.io/doc/usage/collect-data.html)

LIBERO 原生采集脚本主要依赖遥操作，不能直接当作自动专家。应先确认已有演示、兼容策略或可实现的训练侧 rollout 包装器；公开数据入口不代表本机已经具备完整数据。[LIBERO 采集源码](https://github.com/Lifelong-Robot-Learning/LIBERO/blob/master/scripts/collect_demonstration.py)、[数据入口](https://libero-project.github.io/datasets)

MimicGen 提供基于演示的任务数据生成，但要求任务接口和演示预处理；可以借鉴，不应宣称直接适配所有 LIBERO 任务。[官方教程](https://mimicgen.github.io/docs/tutorials/getting_started.html)

DAgger 的核心是专家为学习器访问状态提供标签，因此必须明确专家来源。[原始论文](https://arxiv.org/abs/1011.0686)

## 针对性采集的最短闭环

1. 用仓库原生协议跑一个可信基线，保存实际策略身份和开发集失败案例；正式测试集不用于反复调参。
2. Agent 根据开发失败提出可控训练条件：起始位置覆盖、操作阶段恢复、视觉变化或少见合法状态。条件需由环境实际支持，不能杜撰 reset 参数。
3. 选一个具备正确动作来源的路线；先采一条/小批成功轨迹，记录尝试、成功、接受与拒绝数。
4. 核查观测、动作、时序、相机、任务标签、成功标记等字段；实际转换并加载训练 batch。只列出 HDF5 路径不算接通。
5. 小规模训练验证新增数据确实被读取，保存产物；评测时核对加载路径、权重身份及策略接口。
6. 同协议比较原始数据、定向增量和必要的等算力对照。只有小实验显示收益才扩大采集，避免大量低质量同质轨迹。
7. 输出真实成功/失败 demo、采集质量表、样本量与分数变化。demo 是运行证据，不代替正式统计。

缺自动专家时不应无限反复规划，也不必立即放弃刷分：可在协议许可范围内检查现有演示质量、任务平衡、采样权重、预处理和兼容预训练策略。额外包装器由 Init/Fix 在隔离源码中实现，再重新核查；不能改评测逻辑、使用测试答案或把失败动作标成专家动作。
