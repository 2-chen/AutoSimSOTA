# Harness 成本审计与优化

更新：2026-10-14。范围是 AutoSimSOTA 的提示组装、Claude Code 运行器、DeepSeek 价格网关、角色会话和 Recorder；不是修改 benchmark、训练参数或实验成绩。

## 结论

可以优化。当前不是“缓存完全没用”，而是角色间差异很大：研究主控反复携带长历史，Recorder 又反复冷启动。应同时降低冷输入、重复角色调用和不必要输出，而不是为了好看的缓存比例保留无用上下文。

本轮已实现无模型的证据分页、稳定角色前缀、Recorder 空工作区/写作技能复用、缓存感知的有界会话轮换，以及按角色费用和脱敏请求指纹统计。尚未发真实模型请求进行优化前后 A/B，不宣称实际费用已经下降某个百分比。

## 2. 对照官方及其他 harness

### 2.1 DeepSeek缓存不是一个手动开关

官方缓存自动启用，依赖已落盘前缀单元的完整匹配；共同前缀可能需要后续请求才能持久化。命中是best-effort，缓存有保存时限。因此不能承诺“固定prompt就必定100%命中”，也不应将旧的64-token块说法当当前实现合同。[官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)

工程含义：固定system、角色工具和稳定指令，把当前事件、时间、预算、证据增量放到后面；保持旧消息/工具调用配对，不在代理层随意删改CLI生成的system或工具历史。实际收益以供应商hit/miss回执为准。

### 2.2 DeepSeek Harness可借鉴，但不能直接当稳定替代品

官方`dsh`采用插件化架构；仓库明确标为开发预览，可能有兼容性破坏。此轮没有安装它、切换生产执行器或复制其源码。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)

值得移植的机制：

- 指令按版本/摘要识别变化，未变不反复注入；新增指令以追加方式保留前缀，加载有明确字节预算。[agent-instructions](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md)
- 优先无模型裁剪过大的工具结果，保留完整原始日志与可追溯替换记录；它减少上下文，不负责判断哪段内容语义最重要。[tool-result-pruner](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-tool-result-pruner/README.md)
- 必须摘要时复用原system、tools、历史前缀，将摘要指令放在最后；摘要也要付费，历史替换会让被改位置之后的缓存失效。[compaction-basic](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/README.md)

这些是机制参考，不代表把DSH默认阈值直接照搬就经过了本项目实测。

### 2.3 其他框架的共同点

Deep Agents强调文件系统承接大结果、按需记忆/技能和隔离子任务；OpenCode把自动压缩做成独立职责。应借鉴的是“上下文治理属于harness”，而不是新增更多常驻Agent。每个额外Agent都有输入、输出及交接费用。[Deep Agents官方概览](https://docs.langchain.com/oss/python/deepagents/overview)、[OpenCode Agent文档](https://opencode.ai/docs/agents/)

## 3. 本次查到的缺口与已落地修改

### 3.1 大证据不只出现在共享上下文

旧 `project_context` 主要处理共享snapshot中的长字符串/列表；请求JSON本身、大型映射和MCP输出仍可完整进入会话。

现在：

- 请求JSON、共享上下文和成功MCP结果都可将大文本/无保护字段的大映射落到内容寻址的不可变JSON证据。
- 给模型短预览、稳定evidence ID、完整读取说明。原内容不通过LLM改写；哈希内容冲突和危险symlink拒绝。
- 约束/协议、权限、预算、当前动作、即时错误与stderr保持inline；含嵌套约束的大映射不整体隐藏。失败工具结果不做新分页。
- 只有实际配置了`read_evidence`的角色才收到分页。decision-only审核和Recorder无读取工具，仍收到完整材料。
- `read_evidence`自身不再分页，防止“为了读证据而不断得到另一个引用”。不修改工具call/result顺序、操作身份或原生回执。
- 去重依据原请求而非分页后的预览；冲突字段不去重，不让模型旧记忆覆盖新预算/协议。

入口：`token_context.py`、`agent_client.py`、`agent_runtime.py`。额外证据属于run，不删除训练数据或原始实验日志。

### 3.2 稳定角色前缀与有界热会话

同角色共享的能力合同/路径安全说明移到任务特定指令之前；请求JSON将所选方法、技能目录和指令置于事件证据之前，成员内容不丢失、不重复。当前snapshot留在后面。能力/schema变化仍使旧会话失效，不通过冻结过期工具定义换取命中率。

原逻辑在最后请求输入达到120k时无条件轮换。现在默认仍为120k；只有最后请求已结算、命中率至少90%、冷输入最多12k、输出不超过8,192 token时，允许热会话保留到240k。达到上限、回执异常、协议/传输失败或能力变化仍重新接入当前证据；不把1M上下文当无限历史空间。

这是保守工程启发式，有单元反例覆盖，不是理论最优策略，也不延长任何付费/GPU/墙钟预算。下一次真实窗口需比较热会话保留后的冷输入、输出长度和有效决策质量。

入口：`context_pressure.py`、`agent_client.py`。

### 3.3 Recorder不再每次重新制造冷启动条件

旧异步写作每次创建UUID工作目录，再做选技能、写作和独立审核。旧回执没有system/工具指纹，**无法证明随机目录就是0%命中的唯一原因**；它是代码可见的前缀变化风险。

现在：

- 同一run、模型、预算配置下复用一个空只读写作工作区；源代码/数据不复制进去，不复用研究子任务快照。
- 写作和Supervisor每次仍是fresh decision-only对话，不复用上一份正文/审核结论；共享缓存前缀与共享对话记忆是两回事。
- 复用Recorder自己此前选择的写作技能与理由，不让关键词替它决定。目录、提示、任务类型、失败类别或所选技能正文改变就重选；技能正文每次读当前版本并核对hash。
- 预算/运行配置变更或worker仍标running时创建新worker，旧目录/费用/预留全部保留。未知旧调用不因新建目录被注销。
- 最新事实和新事件仍重新写报告，独立事实审核仍执行；仅省掉不变目的下的重复选技能请求。实时事实页、表格、曲线和媒体发布不依赖新增LLM调用。

入口：`recorder.py`。缺上游/API/预算时沿用事实页，不为写作循环购买重试。

### 3.4 让优化能被测量

网关在实际转发请求上记录system、tools、首条message及envelope的SHA256和字节数，随已结算/未知回执保存。它不输出密钥、路径、正文、工具参数、预测或视频。字节数不是token数，指纹不是provider缓存命中证据。

`token_usage`新增按角色的原记录费用、未知预留、输出/费用份额、输入均值/P95/最大值、指纹覆盖率及不同前缀数量。旧请求缺指纹显示missing，不能记成稳定。它只读回执，不改价、不释放预留，不把本run合计充当继承账本总额。

入口：`request_fingerprint.py`、`deepseek_gateway.py`、`token_usage.py`。

## 5. 下一轮成本验证及后续工作

优先度按“每个有效实验的总费用”，不是按缓存命中率排行：

1. **小额前瞻验收**：在获准的真实执行窗口中固定Flash、相同任务/证据规模和预算，记录至少连续几轮Scheduler、Recorder写作/审核的usage、指纹、延迟、格式失败、有效原生进展。旧run不做科研成绩A/B，保留旧账本；总额度与过期墙钟先处理。
2. **主控的输出与重复调查**：Prompt要求最短完整schema、引用证据ID、一次解决一个未知连接。先区分provider思考/可见输出和有用工具链，再考虑请求级输出控制；不能把原用于最终JSON的`max_tokens=1200`直接压到整个多工具研究请求，造成截断和更贵重试。复杂Scheduler/Fix推理模式本轮未关闭。
3. **增量指令/上下文**：固定身份的源码/技能只传变化摘要，权威当前预算、协议、active jobs和恢复连接仍显式保留；补跨恢复的时效/引用核验。不要将本轮字节分页宣称为已经实现全部语义摘要或完整差量历史。
4. **经济型compaction**：仅在预计未来节省超过摘要本身与重新暖缓存费用时触发。摘要请求需保持原system/tools/历史前缀，尾部追加指令；原日志不删，保留工具配对、活动作业、ID、失败原文、协议和未知项。当前CLI拥有内部历史，本轮没有未经支持接口改写其transcript。
5. **工具schema与程序化批量读取**：先看`tools_bytes`、调用次数、重复源码ID。大注册表才考虑按需声明/能力搜索；多个独立CPU读取可审计地批量，不捆绑训练/采集/评测授权。必须做同等质量对照，不能为了省调用漏验模型加载和数据消费。
6. **运行器比较**：如指纹证明CLI冷启动仍主导费用，可在隔离对照中测试DSH或专用无工具JSON后端。上线前必须保留转发前预留、即时usage journal、父子账本、只读审核、取消/恢复与证据完整性；不另开一套不计费的快路径。

不做：盲目升模型、追求100%命中、无限保留长历史、删除错误证据、让摘要取代计分、为低成本关闭独立审核、将未知预留当余额，或根据正在运行的留出结果调整数据。
