# 失败驱动的数据获取与筛选：方法与实验协议

状态：P0系统合同已实现与回归；P1真实RoboSyn试点于2026-10-08 21:29北京时间由队列自动启动，22:22环境声明探针通过，现进入原生train命令推导/验证。实际仿真与实验数值尚未验收；合同通过不等于真实具身实验闭环通过。新的确认预留修复与本轮人工框架刷新已单列记录，不将此开发试点当冻结无干预主表。

## 1. 要回答的问题

给定可复现的仿真仓库、允许的初始训练数据、原生专家/轨迹生成器与固定总资源，Agent 能否从开发集失败中决定**获取什么数据、保留什么数据、何时停止获取**，以更低成本获得更高的独立评测成功率？

不把“多 Agent”“会安装环境”“更多数据通常更好”作为核心创新。不承诺所有仓库都有自动专家，也不以自动下载官方数据冒充自主采集。

暂名 **Failure-Driven Acquisition and Selection（FDAS）**。它是待验证的方法设计，不是已有实测成立的算法。

## 2. 与已有工作的关系

- [AutoSOTA](https://arxiv.org/abs/2604.05550)：资源、目标、初始化、监控、修复、构思、调度和审核提供基础框架。本项目从仓库出发，不再复现论文定位过程；论文贡献不重复认领这八类职责。
- [MimicGen](https://arxiv.org/abs/2310.17596)：少量示范的自动扩充。能作为数据供给后端，不能把其生成机制算本项目创新；只有任务接口和子任务标注满足时才适用。
- [RoboTwin 2.0](https://arxiv.org/abs/2506.18088)：专家代码与随机化生成数据。用作原生专家后端；不能把仓库本身的生成成功算 Agent 贡献。
- [DataMIL](https://robin-lab.cs.utexas.edu/datamodels4imitation/)：任务相关的数据选择，以目标示范验证损失为代理、使用 datamodels 估计影响，包含轨迹/子轨迹聚类与共同训练。完整复现需要其源码和实际额外计算，不将简单去重标为 DataMIL。
- [RESample](https://arxiv.org/abs/2510.17640)：覆盖引导探索和恢复轨迹扩充。已有“补充失败恢复数据”的贡献，因此 FDAS 必须证明跨仓库的可执行决策、获取与筛选的联合收益和单位成本优势，而非仅更换为 LLM。

核心可证伪假设：失败条件所指向的新增数据比相同专家、相同合法域和相同保留数量的随机新增数据更有价值；筛选带来超过单纯扩量的收益；这些决策能迁移到未用于开发的任务/仓库。

## 3. 系统职责与运行方式

| 角色 | 必须负责 | 不能替代的证据 |
| --- | --- | --- |
| Scheduler / 主 Agent | 掌握目标、执行和版本；选择采集/筛选/训练轮次；合并子 Agent 建议 | 计划不是执行，子 Agent 的建议不是认证 |
| Data | 查找原生专家、可调采样条件、转换和 loader；解释开发失败；提出目标、质量和混合方案 | 低分不是原因；失败动作不是专家标签 |
| Resource | 估算并重新分配局部预算；包括失败采集、筛选、训练、评测与 LLM | 不清账、不增总额、不隐瞒等待与启动成本 |
| Init / Fix | 接通原生路径；按稳定错误 ID 修复并复验原操作 | 修复系统不能改指标、划分或伪造数据 |
| Supervisor | 独立检查来源、分组、消费、实际策略、协议和对照公平性 | 注册条数、内部训练成功率不能替代独立 rollout |
| Recorder | 中文说明问题、选择、成本和结果；展示真实 demo、数据对比及未完成项 | 不能把未执行填零或把生成成功当策略提升 |

### 一轮方法

1. **冻结输入与协议。** 记录仓库 revision、原始数据身份、原生入口、允许的训练域、评测定义、初始权重与预算。正式结果只能来自固定系统版本。
2. **真实基线。** 验证训练产物→实际加载→rollout→指标。可复现官方 checkpoint 与本地训练基线分开标记。
3. **失败观察。** 使用开发 measurement 与其封存诊断；按实际可观察字段调查阶段、物体/起始条件、视觉扰动或动作偏离。仅有成功率时标记原因未知，安排有界诊断，而不是编造失败类型。
4. **提出可执行目标。** Data 查阅原生源码，区分 reset 级专家、能从偏离状态接管的纠正专家、轨迹适配、仅学习策略自举和仅人工遥操作。只允许前端确实支持的配置，不固定 benchmark 名称分支。
5. **登记 campaign。** Scheduler 调用 `register_data_campaign`，保留起始开发证据及获取/筛选假设，并预先声明 targeted/random 对照、接受 episode 数、配方、种子和成本记账规则。登记不启动仿真，也不批准因果解释。
6. **小试供给链。** 原生 `collect`→`prepare_data`→真实 loader batch；验证动作与观测对齐、完整 episode 边界、专家成功条件、重复/非法样本、任务和训练划分。先验证可用产出率，再扩大数量。
7. **版本化筛选与混合。** 原始输出不覆盖；筛选结果保留父版本、规则和封存 `AUTOSIM_DATA_PROFILE`。分组去重按完整轨迹/生成源族处理，不能把同一轨迹帧分到不同 split。混合权重是意图，实际来源曝光另记录。
8. **实际训练与计分。** 原生训练显式消费 `data-version:<id>`；loader 发出真实字节身份与 sample/batch/source 消费证据；独立评测加载该训练对应权重。长训练走正式作业，不重复拿整个训练作入口验收。
9. **记录 observation。** 调用 `record_data_campaign_arm`，关联采集/筛选与训练版本、已完成开发测量。不能用同一 measurement 代表两种方法/种子；不自动更改 best 或原基线。
10. **决策与独立终验。** 比较收益、产出率、实际样本曝光和全成本；低收益时改目标/筛选或停止采集，仍可选择其他优化。主 Agent 按证据决策，不能硬规定“先采固定 N 条”。最终 held-out 一次性打开后不再采集/调参。

代码入口：`autosim/autosim/research/data_campaign.py`、主控操作目录及 Data/Scheduler 提示。已有 data_lineage/data_versions/native_jobs/measurement 身份链负责原生执行，不新建第二条 benchmark 专用管线。

### 当前实现的精确边界

campaign 已链接主控和 RUN.md，但获取参数/筛选语义由 Agent 查证并通过已有原生阶段执行。注册不是自动生成专家，不新增 GPU 权限，不替代原生 collector，也不修改已冻结的旧 run。已打开 held-out 的 run 禁止新 campaign/arm；记录不可覆盖，证据改变则投影不展示结果。

页面显示的 full episode 是原生报告计数，不能自动推断不重叠新增数量。对应数据可实际消费，但独立公平性仍待 Supervisor 检查：声明的种子是否生效、原分布混合是否一致、工作量是否一致、评测是否匹配。Registry 不以关键词/数字大小做科学批准。

## 4. 实验设计

### 先做可行性门槛

首个真实采集试点优先选经源码验证拥有自动专家的 RoboSyn/RoboTwin 任务；选择依据是能力，不是名称。LIBERO 先核验训练/评测和可用示范；没有原生纠正专家时作为数据筛选或资源访问轨道，不假称自动采集已支持。

首轮必须形成：**新产出的独立轨迹→独立派生数据版本→真实 batch 消费→实际权重加载→冻结开发评测**。产物分别保留稳定 ID 和身份。不因完成 collector 就升级为闭环成功。

### 两类公平性研究不能混为一谈

| 研究 | 比较条件 | 回答的问题 |
| --- | --- | --- |
| 等接受数据量 | 固定相同新可用 episode 数、专家、合法域、质量底线、官方数据、训练初始化/更新与评测 | 目标与筛选是否提升数据价值？收集成本额外如实报告 |
| 等总计算量 | 包含失败采集/转换/训练/评测的 GPU 预算；同时报告 CPU/墙钟/LLM 费用；允许获取数量不同 | 整体决策是否更高效？不能称等数据量 |

各类研究分别预登记，不强行同时等数据量且等算力；定向采集更难造成额外成本本身就是结果。

主对照：固定官方数据配方、不增数据的等计算续训、随机扩量+共同质量底线、失败驱动扩量+共同质量底线、失败驱动扩量+目标筛选（完整 FDAS）。主 Agent、底层模型、工具权限、初始化和总资源保持一致。普通 coding Agent 作为系统级辅助对照，不取代直接的数据方法消融。

消融：去掉失败条件（随机目标）、去掉任务相关筛选、固定采集/训练预算、不使用纠正数据、去掉数据消费核验（只做诊断性开发实验，不能作为不可信正式分数）。保留原分布任务检查是否灾难遗忘。

### 规模与统计

- 先 1 个任务、1 个种子验证合同与耗时；这是 pilot，不是主表。
- 成功后先 2 类任务、每类至少 2 个任务、3 个训练种子。优先完成 targeted/random 的直接比较，再扩展算法对照。
- 任务 holdout 与仓库 holdout 分开报告。仅换同仓库任务不能声称跨仓库泛化；正式仓库留出在系统/技能冻结后才打开。
- 同初始状态配对 rollout 报告差值与置信区间；训练 seed 间均值/标准差单独报告，不能把 episode 数当独立训练重复数。多轮选择存在偏差，最终独立终验不可复用为训练反馈。
- 每一单元报告闭环状态、可用新 episode、尝试/成功/拒绝、重复率、覆盖、原/新实际曝光、成功率、LLM/GPU/CPU/墙钟、干预次数和首个分数时间。
- 不在没有 matched-protocol 官方/公开强基线时称 SOTA。主张可改为相对数据效率/自动化，不因论文题目需要而挑选最有利结果。

## 5. 数据与研究记录

每批原始数据保存 native producer evidence、专家/初始条件、attempt/accepted/rejected 及原因、字节身份、许可和训练划分。开发失败仅用于目标推断，不将评测轨迹直接加入训练；纠正样本由允许训练状态的专家重新采集。需要中途状态恢复时先证明专家可接管。

筛选可由 Agent 选择：完整轨迹有效性、内容/来源族去重、稀缺失败条件覆盖、时序连续性、任务相关估计。不能粗暴删等待动作或把画面相似当动作监督等价。DataMIL/覆盖模型是可选研究假设，未经实现与消费验证不能贴其名称。

空间不足先释放已审核的可再生成中间权重，不删除唯一数据或 scored/final/resume 产物。大文件与源码隔离连接；原始资源只读。备份存在需实际校验，不用符号链接声称有备份。

RUN.md 使用中文展示“为什么采这类数据”“实际采到多少”“哪些进入了训练”“相比随机是否值得”。待执行显示待执行；图表来自已观察值；真实视频通过既有封存 demo 路径，由 Agent 主动提交，不能以介绍动画充当实验录像。
