# Harness 与规则堆的区别

这份文档写给下一个改这套系统的人,包括未来的我自己。它记录一条判据,因为这条判据在一轮工作里被违反过很多次,而每一次违反看起来都像是修 bug。

---

## 一句话

**规则描述系统自己的契约;harness 让模型去发现关于世界的。**

区分两者不需要道德判断,只需要问一句:**这条代码里的事实,是关于我们的,还是关于某个仓库的?**

| | 例子 | 该不该写在代码里 |
|---|---|---|
| **关于系统自己的契约** | 「Python 解释器 + `.sh` 文件」在静态上不可能跑通;环境值里的 `${VAR}` 按 shell 语义展开;空优化空间不是空间;`where` 字段必须是**一条**路径 | **该**。这些是系统自己词汇表的约束,和哪个仓库无关,而且它们**通用地成立** |
| **关于某个仓库/这台机器的事实** | 「这台机器上有哪些 conda 环境」;「入口旁边那张表的键是什么」;「venv 里那个二进制叫什么名字」 | **不该**。这不是通用知识,是**可以被查到的知识**。写进代码就等于把系统钉死在见过的约定上 |

第二类每加一条,系统就多一个"只在见过的仓库上成立"的假设。下一个仓库换一种约定,就得再写一条 —— 这就是规则堆。

---

## 判据:它是不是替模型去看了?

第一类和第二类的分界,不是"抽象程度",而是:

> **这段代码是不是在替模型执行一次它自己就能执行的观察?**

`environments_this_machine_has` 扫描 `~/miniconda3/envs/` —— 那是一条 `conda env list`,模型会打。`keys_a_nearby_table_has` 打开入口旁边的 JSON —— 模型会开。`executable_the_environment_ships` 在 site-packages 里找二进制 —— 模型会找。

**这三个函数都是"模型不能去看"的替代品。** 它们被删除的那一刻,系统的泛化能力上升,因为它不再需要预先知道任何一种约定。

修法不是写更多 helper,是**把"去看"这个动作给模型**:`diagnose` 可以返回 `{"look_at": ...}` / `{"look_at_dir": ...}` / `{"run": ...}`,循环执行它要的、把结果贴回去、再问一次。

---

## 三条随之而来的设计

### 1. 检索在推理之前

一个失败类已经解决过,就不该让模型从零再推一遍。失败记忆按**归一化签名**(`ModuleNotFoundError: No module named '…'`)跨仓库检索,并且同时记住**试过但没用的**,这样已经排除的分支不会被再提一次。

签名必须对**名字**盲:同一个 `KeyError` 在不同仓库里是不同的人猜错同一个约定。名字属于"例子",不属于"失败"。

### 2. 观察者站在循环外面

循环里的每一次尝试只能看到自己为什么失败。看不到"最近十一次都是同一类改动"或者"状态从第四轮起就没动过"。

所以 `monitor` 读循环自己的轨迹,给出**关于搜索形状的句子**,而**不是关于修法的句子**。这个区别是整个模块的要点:一个说"把 PYTHONPATH 设成 X"的监控者,已经替能读仓库的那个东西做了决定;一个说"最近六次改的都是环境,而环境没有变"的监控者,告诉它一件它自己看不见的事。

### 3. 一个提示词只做一件事

`REVISE_SYSTEM` 一度长到九千字符、同时扛十一个关注点 —— 查看协议、五个字段、障碍规则、失败记忆、监控、三类具名失败、若干自相矛盾的警告。它的回答从"入口是 bash 脚本而命令用 Python 跑它"退化成"Let me look at what actually failed"。

**这是被观测到的塌缩**,AutoSOTA 整套多 agent 架构就是为它而建,并且给了它名字:*monolithic LLM prompt collapse under long-horizon scientific execution*。修法是拆角色:诊断回答**是什么**,修订回答**怎么办**。两个提示词各三千字,好过一个大的一万字。

## 关于"模型会不会做错"

会的。所以有些东西**必须**是代码,而它们仍然是第一类:

- **静态不可能**:`python script.sh` 跑不了。提示词写了三遍,模型照写。改成**拒绝运行**之后立刻好了。**告诉模型别做什么,比拒绝做那件事弱。**
- **静默的错误值**:`locals().get("manifests")` 返回 `None` 而看起来像答案;`"A and B"` 通过所有检查变成一条不可能存在的路径;一个空的优化空间通过了 `space_from`。这些是**系统自己的词汇表**可以拒绝的东西。
- **阶段依赖**:一个可用的 `prepare_data` 而测量循环从不调用它 —— 那是一个系统持有的、却从不执行的阶段。这不需要模型判断,需要把它接上。

---

## 什么时候该停下来问自己

改这一段的时候,如果发现自己在写:

- 一个从**错误信息**里提取某个名字的函数 → 那是"去看"的替代品。给它查看的能力。
- 一个**枚举某台机器上有什么**的表 → 同上。
- 一条"如果 X 就让模型做 Y"的分支 → 除非 X 是系统自己的契约,否则那是一条会被下一个仓库证伪的规则。
- 一个越来越长的提示词段落 → 拆角色,不要加句子。

最后一个反过来的信号:**如果一段代码里的事实,换一个仓库就不成立,而它又不是通过观察得来的,那它就是一条迟早会错的规则。**
