# Benchmark shapes

When you meet a new benchmark, these are the dimensions along which it can differ. Read
each one off the repository rather than assuming it — several have no default, and two
of them change what a success rate *means*.

## Universal — safe to assume

- **Success is a scripted predicate over simulator state.** LIBERO parses it from a BDDL
  goal, robomimic calls `env._check_success()`, RoboSynChallenge calls
  `is_task_success()`, RLBench registers `ProximitySensor` conditions. No benchmark found
  used a reward threshold or a learned success classifier.
- **The metric is per-task success rate.** Dense reward exists in some benchmarks but is
  a training affordance, never the reported number.
- **Episodes end by horizon truncation**, not natural termination. robomimic hardcodes
  `is_done() -> False`.
- **Observations are proprioception plus two-view RGB**, wrist and external. Depth is
  optional and always secondary.

## Varies — read it, never assume it

**1. Initial-state distribution — read this one first.**
`frozen set` (LIBERO ships 50 fixed states per task and walks them in order) ·
`sampled per episode, seeded` (robomimic, RoboSynChallenge) · `sampled, optionally
frozen by a flag` (RoboSynChallenge's `eval_fixed_episode_seed`).
These are not interchangeable: they change the variance of the estimator and hence what
a given success rate means. LIBERO's choice is deliberate and documented ("for
benchmarking purpose, we fix a set of initial states"); robomimic's opposite choice is
equally deliberate. Record which one you used.

**2. Task discovery mechanism.** `code registry` (LIBERO's task map) · `config file`
(RoboSynChallenge `gym_config.json`, RoboTwin per-task yaml) · `metadata embedded in the
data` (robomimic reads `env_args` out of the HDF5 — there is no task list at all) ·
`gym-registered id` (Meta-World) · `task subclass + scene file` (RLBench). Five live
categories; there is no standard task-list format to target.

**3. Where the goal lives.** `declarative spec parsed at runtime` (LIBERO BDDL) ·
`imperative code` (robosuite `_check_success`) · `config predicate list`. LIBERO is the
only one that exposes the goal as data you can read without executing the environment.

**4. Expert data source.** `human teleoperation` · `scripted or motion-planned` ·
`generated by recombination` (MimicGen and relatives) · `trained RL agent`. Four
distinct pipelines, not one interface. A related split matters more than the file
format: some benchmarks ship pre-collected data to download, others expect you to
generate it.

**5. Action-space declaration.** `derived from the instance` (robomimic reads
`action_spec`) · `named control parts in config` (RoboSynChallenge's
`env.control_parts`) · `convention implied by a controller name` (LIBERO's 7-dim
`OSC_POSE`). Dimension values seen: 4, 7, 14, 16.

**6. Serialization.** HDF5 (with dialects — robomimic writes `next_obs` and named
`mask/` subsets, LIBERO writes neither) or columnar parquet + mp4. Two families.

**7. Camera names, resolution, and whether calibration is declared.** `agentview` +
`robot0_eye_in_hand` · `head_camera` + `left/right_camera` · `cam_high` +
`cam_*_wrist`. Never hardcode one.

**8. Episode count and horizon.** Observed: 20/600 (LIBERO repo default), 50/600
(common LIBERO practice), 50/400 (robomimic), 100/per-task (RoboSynChallenge). All
benchmark-specific.

- **Language instruction is NOT universal.** It is in LIBERO, RoboSynChallenge and
  RoboTwin, and absent from robomimic's core tasks. Treat it as optional.

## Habits that look like rules but are not

Each of these is a real convention somewhere and a mistake if generalised.

- **"50 episodes"** is not a statistical convention. LIBERO ships exactly 50 fixed init
  states, so 50 episodes is 50 distinct conditions; on a benchmark that samples initial
  states, 50 episodes is 50 draws from an unbounded space. Different quantity.
- **"Report the best checkpoint"** — robomimic's `Success_Rate-max` is the maximum over
  training, i.e. oracle checkpoint selection. Not comparable to a single-checkpoint
  number.
- **"~10 source demonstrations"** is MimicGen-specific. Other generators in the same
  family work from one.
- **LIBERO's fixed-and-ordered init states** are what allow a small probe with a learned
  per-task embedding to score near the top by lookup rather than by following
  instructions. Treating that protocol as best practice imports its failure mode.
- **Absolute success rates do not transfer across benchmarks.** Any cross-benchmark
  claim has to be a delta measured on a shared protocol.
