# 确认训练真的产生了可评测策略

方法性指引。robomimic 的研究指出训练目标与评测目标不一致会影响停止点选择，不能只凭 loss 挑选最优策略。[原始研究](https://arxiv.org/abs/2108.03298v2)

## 先问这轮实际训练了什么

核对实际加载的数据集、样本数与抽样曝光，模型家族/可训练参数、初始化 checkpoint、优化器、有效 batch、梯度累积、更新步数和学习率调度。epoch 的含义随 sampler、数据量和 drop_last 变化；增加数据而保持 epoch 不变往往也增加计算。

训练小试验证 forward/backward、非零有效更新、保存和独立重新加载；小试不是收敛评测。必要时在训练子集作过拟合诊断，但不能用它的得分替代开发/正式指标。

## 选择改动

- 明显欠训练：预测足够训练量的成本，主 Agent 决定延长/续训，不因局部短时限就换模型。
- loss 异常：检查标签、归一化、梯度、学习率与数值精度；不要同时改五个参数。
- train 好而 dev 差：考虑训练侧增强、正则化和数据覆盖，检查泄漏与重复样本。
- 换 RNN/Transformer/动作头：新架构不意味着原 checkpoint 可用。先验证官方同族权重；无权重则估计从头训练成本并明确登记，不能把随机初始化当续训。
- EMA/raw 权重、best/last checkpoint：只比较源码实际支持且协议允许的选择，并固定选择依据。

## 交付一个可追溯的产物链

绑定训练 attempt、代码与 resolved config、数据版本、初始权重、更新量、产物指纹；随后核对评测进程实际加载的文件及模型配置、rollout attempt、episode 身份与指标回执。仅存在一个 .pt 文件或命令里写了它的路径不够。

局部预算不足时提交受支持的长期训练作业；完成后仍须走正式计分与身份核验接口。不能通过生成 score 文件绕过核验。恢复应明确是完整 optimizer/scheduler/RNG 恢复还是仅权重 warm-start，两者计算预算和训练语义不同。

正式留出集不参与 checkpoint 选择；开发阶段频繁选优需在最终报告披露选择次数，最后做独立确认。停止无学习信号的作业前先检查更新计数、I/O、保存与评测阶段，不能把暂时无日志直接当死锁。
