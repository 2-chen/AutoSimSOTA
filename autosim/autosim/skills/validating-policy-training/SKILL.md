# 确认训练真的产生了可评测策略

方法性指引。robomimic 的研究指出训练目标与评测目标不一致会影响停止点选择，不能只凭 loss 挑选最优策略。[原始研究](https://arxiv.org/abs/2108.03298v2)

## 先问这轮实际训练了什么

核对实际加载的数据集、样本数与抽样曝光，模型家族/可训练参数、初始化 checkpoint、优化器、有效 batch、梯度累积、更新步数和学习率调度。epoch 的含义随 sampler、数据量和 drop_last 变化；增加数据而保持 epoch 不变往往也增加计算。

训练小试验证 forward/backward、非零有效更新、保存和独立重新加载；小试不是收敛评测。必要时在训练子集作过拟合诊断，但不能用它的得分替代开发/正式指标。

## 基线异常要形成可执行诊断

`baseline_diagnosis.status=required` 时，先读取交接中的原生证据 ID，核对封存配方、完成计数、实际训练人口、已加载策略及评测条件。将 training/data/policy/evaluation 四项发现、未知项和下一步操作交给 Main，用 `record_baseline_diagnosis` 记录；没有新证据就不要再跑同样的短训。允许明确标注不确定性的本地小预算优化，不允许把诊断报告当官方复现或数据消费认证。

既有/官方数据与新增数据一样可能接错：没有 `data-version` 句柄只意味着尚无版本消费证明，而不是“不需要检查”。先沿授权资源视图连接真实 loader，再登记 existing/official 版本；消费计数来自真正读入的 batch，不能用目录元数据、请求数量或 argv wrapper 的打印替代。在线学习则追踪原生经验来源，不强制改造成示教数据管线。

需要校准参考时，`evaluate_baseline_reference` 使用已审核的 episode 数和独立封存协议；本地搜索协议、原基线和最佳版本不变。参考失配时检查同族权重、配方、观测动作/归一化、reset/控制链，不把低分直接归为框架崩溃。学习预算由源码配方、实际工作量及实测成本决定，不设跨仓库固定步数。

## 选择改动

- 明显欠训练：预测足够训练量的成本，主 Agent 决定延长/续训，不因局部短时限就换模型。
- loss 异常：检查标签、归一化、梯度、学习率与数值精度；不要同时改五个参数。
- train 好而 dev 差：考虑训练侧增强、正则化和数据覆盖，检查泄漏与重复样本。
- 换 RNN/Transformer/动作头：新架构不意味着原 checkpoint 可用。先验证官方同族权重；无权重则估计从头训练成本并明确登记，不能把随机初始化当续训。
- EMA/raw 权重、best/last checkpoint：只比较源码实际支持且协议允许的选择，并固定选择依据。

## 交付一个可追溯的产物链

### 先确认选对产物，再解释分数

“有正更新计数”只证明训练发生过；“加载哈希一致”只证明加载的是选中的文件。两者都不证明选中了本轮目标策略。Scheduler 与 Supervisor 要先查看完整的候选/计数目录，沿原生保存源码区分中途快照、实际完成终点、EMA/raw 和原生 best 规则；不能根据目录顺序、文件名或任意一个正数挑选。目录被截断时先请求完整或分组的证据，不把可见前缀当全集。

记录本轮计划训练量、实际完成量、所选产物的完成量与计数单位。只有源码证明单位相同才能比较 steps、updates、epochs；目标配置不是完成证据。终点计数与另一个更大计数冲突时先解释生产者/续训关系，不宣称已经完成目标；合法提前停止或 native best 必须提供独立于正式留出分数的选择依据。

若已训练到目标却评测了早期快照，这是产物交接故障，不应立即换架构、增采数据或重复训练。把训练 attempt、错误选择回执、正确候选及源码依据的稳定 ID 交给 Fix，优先重新审核已有产物并发起单独的纠正评测。保留原分数及原身份，记录新测量与旧测量的关联；不要悄悄改写基线或把错误产物的分数当成假设失败。

效率顺序：先读小型计数/配置与保存源码，再对选中的产物做指纹和独立加载核验；不为了筛选候选把每个大权重都复制、哈希或完整 rollout。先验证接口的小试不能替代协议要求的正式评测。若证据不足，报告具体缺口并请求修复，不用低分掩盖身份问题。

绑定训练 attempt、代码与 resolved config、数据版本、初始权重、更新量、产物指纹；随后核对评测进程实际加载的文件及模型配置、rollout attempt、episode 身份与指标回执。仅存在一个 .pt 文件或命令里写了它的路径不够。

局部预算不足时提交受支持的长期训练作业；完成后仍须走正式计分与身份核验接口。不能通过生成 score 文件绕过核验。恢复应明确是完整 optimizer/scheduler/RNG 恢复还是仅权重 warm-start，两者计算预算和训练语义不同。

正式留出集不参与 checkpoint 选择；开发阶段频繁选优需在最终报告披露选择次数，最后做独立确认。停止无学习信号的作业前先检查更新计数、I/O、保存与评测阶段，不能把暂时无日志直接当死锁。
