# 具身仿真提分与实验提效：可迁移技巧调研

调研日期：2026-10-06。定位：已有仓库、已有运行资源、以提高合法 benchmark 指标为目标的 Agent 方法库；不是从零复现所有论文，也不是排行榜核验。本次没有启动训练、仿真或收费模型调用，没有新增本地增分测量。

## 结论：优先改善数据与反馈回路，而不是频繁换大模型

我的工程判断是：在单 GPU、有限预算、仓库间接口不一致的情况下，优先寻找已有策略和原生执行器能支持的低成本机会，然后才考虑结构改动和新的在线算法。这个优先级是结合迁移成本作出的判断，不是某篇论文证明的通用最优顺序。

最值得尝试的五类机会是：选对已有训练产物；调整合法的推理/反馈设置；用少量针对性数据修复失败阶段；使新数据真正获得训练曝光；减少 I/O、重复训练与低信息量评测。数据优先也有前提：原生专家、轨迹适配或合法反馈必须真实可用。固定数据协议不能靠额外采集提分。

## 1. 工作证据与迁移边界

这里只依赖论文、作者项目和官方源码/文档。未逐项复跑论文的全部实验；涉及具体实现时还需核对当前 checkout 的版本。经典工作仍有价值，但不能据此声称它们是 2026 年最新 SOTA。

## 2. 先不重训：已有产物上的便宜候选

### 2.1 checkpoint、EMA 与选择规则

先纠正终点、native-best、raw/EMA 和实际加载身份。已有 EMA 只有在训练确实更新、保存、加载时才是合法选项；临时把未更新的初始化副本叫 EMA 没有意义。查看开发 rollout，而不单靠训练 loss 选择。小规模比较预先约定的少量训练点，不把每个保存点都跑完整仿真。

这一步既可能是修复，也可能是正式允许的策略选择。修复加载错误不能包装成新的算法增益。若旧基线的 checkpoint 选择有误，保留原记录，另外报告纠正后的基线；不能悄悄降低或覆盖对照。

### 2.2 执行 chunk 与反馈频度

预测一长段动作不意味着必须全部开环执行。接触/插入偏离后恢复太慢，可以比较更短的合法执行段；动作抖动时比较原生 temporal ensemble，同时检查夹爪切换与滞后。训练结构、队列和动作对齐决定哪些设置能在已有权重上测试。不能修改冻结的物理时步、控制频率和 episode horizon。

### 2.3 扩散采样步数与同一观测的编码复用

若源码支持，比较少量采样预算及兼容采样器，记录成功率与端到端推理延迟。不要只测 denoiser 耗时，忽略图像编码、传输和环境步。DP 官方图像策略先编码观测再迭代去噪，检查本地 fork 是否在每个去噪步重复做视觉编码；若已经复用则不再“优化”一次。

同一次决策内复用相同观测是工程候选；跨新观测缓存旧特征会改变控制策略。训练时若 encoder 在更新、存在随机增强或训练态统计，也不能长期缓存成固定特征。蒸馏是后续高成本候选，不是直接少跑几步的别名。

## 3. 少量高价值数据，通常比盲目扩量更值得试

### 3.1 按失败阶段采集，但不要只采最难状态

用开发失败形成“条件 × 阶段 × 可恢复性”分组。例如抓取前定位失败、夹爪闭合后滑落、转运后放置失败分别需要不同演示。选训练分布内的缺口，保留原分布和容易成功场景作为混合。难度高但专家也无法完成的状态可能只消耗预算；先测真实产出和恢复可行性。

一个轻量试验可以比较：不增采的等计算续训、普通新增演示、针对性新增演示。全部不是每轮必做；主 Agent 依据疑问和剩余资源选择必要对照。开发胜出后再分配更多采集资源，不先攒上千条才训练。

### 3.2 让专家演示恢复，而不是离线给标签加噪声

DART 的关键是扰动改变真实访问状态，专家在这些状态继续提供恢复动作；离线给已记录 action 加高斯噪声没有得到对应状态和正确标签。仿真可以考虑合法的微小动作/训练初态扰动，但应保留 expert target 与实际 executed action 的来源，确认 loader 读的是哪一种。没有专家恢复能力则改用正常训练场景的独立演示，不能冒充 DAgger。

噪声只作为候选。按训练/开发偏离尺度、小试产出率与动作限制定强度；全任务大噪声可能破坏接触、增加失败并污染 BC。先小批次比较无扰动与一种有理由的扰动，再决定是否扩量。

### 3.3 轨迹适配也有可调的“连接质量”

MimicGen 的源子任务片段选择、子任务边界和衔接影响生成。已有兼容接口时，可在保持同一训练情境预算的前提下比较原生可选片段策略/衔接设置，观察碰撞、漂移、成功与多样性；不能把提高生成成功率等同提高策略分数。没有对象信息、子任务信号或匹配控制器时先估算接入成本。

若官方已生成训练数据符合协议且可加载，可以先连接该资源验证学习链路，再研究自采路线；不为证明“自主”把同一资源全部重新生成。下载、格式转换、存储及校验仍有成本，下载数据也不算本系统自采成果。

### 3.4 采样曝光、去重和课程

少量纠错数据在大库中按默认比例混合可能几乎不被采样。测真实曝光，考虑原生 dataset 权重或 sampler；比较原任务保持与目标失败阶段改善。长时间静止片段、重复轨迹和数据异常可调查，但停顿也可能是有效等待/稳定接触，不能无依据删帧或重定时。训练序列窗口的连续性和动作对齐必须保留。

课程可先覆盖可恢复偏离，再提高训练侧难度；若协议允许，使用场景分组采样而不是改变正式测试分布。DataMIL 提供“数据价值看下游任务”的证据方向，但完整 datamodel 成本未在本机量测；本系统的小混合对照只是工程近似，并非实现该算法。

## 4. 需要训练的低成本策略技巧

先核对标签/归一化，再比较训练量、学习率、scheduler 与梯度异常；没有足够更新的模型不要急着换架构。小子集过拟合用于连接诊断，不能作为正式分数。epoch 要读源码：固定更新数的 epoch 与遍历数据集的 epoch 不等价。

视觉失败可尝试当前实现已支持的轻量 crop/shift；颜色相关指令不默认 color jitter，精密空间任务不默认旋转/翻转。历史序列中的随机变换要考虑时间一致性，多视角还需考虑标定几何；相关约束由具体模型决定，不设通用同步规则。DrQ 的证据主要来自像素 RL，迁移到 BC 是待验证假设。

预训练 encoder、增加 proprio、历史记忆或合法深度可能有帮助，但都要检查资源、输入协议、初始化兼容性和重新训练成本。已有框架不支持时，以隔离候选补丁和验证清单提出，不让技能假定新功能已经存在。缺少必要资源时寻找获准官方资源或明确推迟，不把随机初始化当官方 baseline。

## 5. 计算提效：先找瓶颈，不能把 FPS 当最终目标

这是工程推断，须小试：

| 情况 | 可尝试的技巧 | 容易适得其反的地方 |
| --- | --- | --- |
| GPU 等数据 | 原生 low-dim/全量缓存、loader worker 与预取、非阻塞传输 | 全图像缓存和 worker 复制使 RAM 爆满；新数据仍读取旧缓存 |
| forward/backward 贵 | 实现支持的混合精度、稳定形状编译、合理 micro-batch | 动态形状反复编译、数值问题、编译成本大于节约；有效 batch 变化影响学习 |
| 仿真/推理贵 | 原生多环境、批量策略推理、同一观测内共享编码 | GPU/CPU/渲染争用；历史跨 episode 串扰；后端变化破坏可比性 |
| 保存/视频/反复评测贵 | 开发侧稀疏评测、预定少量代表 demo、原生保存频率 | 删除正式身份/恢复点；测试只录成功，或者关闭必需的观测渲染 |
| 多次候选重复做相同工作 | 验收缓存、资源显式连接、训练完成后纠正交接、恢复优化器续训 | 仅按文件名缓存；把 warm-start 当完整 resume；沿用过期源码/协议 |

Profiling 应有界，避免全程细粒度 tracing 的附加开销；分别计冷启动和稳定阶段。AMP、编译和缓存不是每次实验的强制准备步骤。纯提速比较同工作量；如果节省用于更多训练，再单独报告更多训练的成本及收益。

回本算例（纯算术，不是本机测量）：编译花 120 秒，每次 rollout 节省 2 秒，至少要超过 60 次才能覆盖编译成本；剩余只有十次评测就应推迟。蒸馏同样比较 teacher/student 总开发与训练成本、剩余决策数和实际端到端节约。

## 6. 搜索效率：少量有解释力候选，逐级增加证据

不要把全部技巧做笛卡尔积。先复用已经知道的失败和学习曲线；根据最不确定的问题，选一到几项能区分解释的实验。低成本执行候选可先测；需要重训的候选以足够产生有效学习的预算筛选。ASHA 可参考已有 [预算技能](../../spending-a-budget-across-ideas/SKILL.md)，但早期 loss 未校准不能跨模型排名。

开发评测可用预先确定的配对初态和小样本筛除明显坏候选，然后扩样本确认。高成功率时尤其要检查计数分辨率：50 回合中的一个成功/失败就对应 2 个百分点，98% 与 100% 不足以凭单次原始比例认定可靠提升。可改进开发侧测量精度或研究失败诊断，但不能因候选难测就改变正式分母。

开发集反复选 checkpoint、推理参数和数据分组会产生选择偏差。预定独立确认或采用有依据的序贯设计，不“多测直到显著”；正式留出不能供 Agent 生成下一条 idea。旧运行没有预定留出时，只能如实标记后验复测/复现，不能补写协议冒充预先设计。

候选可按“预期价值、区分问题能力、成本、实施风险”定性排序；没有校准经验时不捏造精确的成功概率/信息增益。预算建议基于当前账本余量、真实吞吐和失败产出，不硬编码每种算法的分钟数。

## 7. 本系统的接入方式与优先级

本次落地是方法指导，不是新执行引擎。主 Agent 看短目录后自主选读，建议每次只读取当前问题需要的一到三项；关键词不决定方法，报告记录理由与拒绝理由。方法正文有足够独立信息；长调研不默认注入上下文，不能假定隔离 Agent 能直接访问宿主 references。

| 当前证据 | 建议首选 | 备选与停止条件 |
| --- | --- | --- |
| 尚无可信 baseline，或实际加载不明 | 输入/动作核对、完整训练产物身份与纠正评测 | 先修链路，暂停新增算法/大规模采集 |
| 策略已有效，接触/恢复失败突出 | 合法执行段比较；可用专家的针对性恢复小数据 | 无专家偏离状态能力，则正常训练场景采集或数据混合 |
| 新数据未见效果 | 消费身份/曝光、质量与覆盖对照 | 不先扩量；旧任务退步时回退或调混合 |
| 训练进度有效但非常慢 | 新增 accelerating-policy-experiments | 实测瓶颈不在 GPU 时不先编译；不重复环境准备 |
| 剩余错误来自未覆盖场景 | 合法多样性采集、轻量增强/历史 | 固定数据、缺资产/输入权限时拒绝对应方向 |
| 原生专家不存在且 BC 有明确上限 | 原生奖励/训练器成立后评估在线微调 | reward 长期无信号、吞吐/兼容性不成立则推迟 |

新增技能负责计算与重复工作；数据、控制、视觉、预算技能各补充对应最小实验。没有设置 RoboSyn/LIBERO/RoboTwin 专用默认参数，没有修改任何 run 的正式协议、计分文件或预算，也没有重启旧实验。

下一次运行的真实验收应回答：Agent 为什么选该技能；生成了什么可执行候选；实际数据/训练/加载/rollout 身份是否贯通；相同成本下成功率或吞吐是否改善。文档与检索测试只能验收技能可用性，不能替代这个结果。
