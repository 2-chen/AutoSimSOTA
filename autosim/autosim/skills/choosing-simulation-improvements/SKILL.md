# 选择值得尝试的具身仿真改进

这是方法路由，不是固定流水线。先依据当前仓库、实验协议、失败证据和剩余预算排序，再按需读取具体技能。关键词只推荐；主 Agent 说明选择理由，也可以不选。

## 先确定要超过谁

区分修复运行、复现基线、超过本机基线、达到可比公开最优四种成果。公开表格只有在任务、划分、观测、动作、数据权限、评测实现与 checkpoint 选择规则一致时才可比较；否则只能报本地改进，不称 SOTA。

记录基线代码/数据/模型身份与开发评测协议。无可靠基线时先接通真实加载和 rollout，不把零分日志当基线。正式留出集不能用于选方案、选 checkpoint 或采集目标。

## 根据证据选择，不按仓库名分支

| 观察 | 优先调查或最小实验 | 按需读取 |
| --- | --- | --- |
| 离线 loss 正常，动作饱和、反向、首步异常 | 核对训练到部署接口；这可能是修复而非算法增益 | aligning-policy-inputs-and-actions |
| 原生专家可用，训练状态覆盖不足 | 小试采集→转换→真实 loader；预算允许时早做数据候选 | connecting-native-data-collection、diversity-before-volume |
| 新数据加入后无变化或旧任务退步 | 实测抽样比例、数据质量与遗忘，不先扩大数量 | weight-the-small-set、quality-needs-reweighting |
| 接触阶段失误、动作抖动、恢复慢 | 小范围比较执行分块、反馈频度或时序融合 | tuning-action-chunks-and-feedback |
| 训练未收敛或候选实际加载不明 | 核对更新次数、恢复状态、模型身份与选择口径 | validating-policy-training |
| 遮挡、视觉漂移、历史依赖 | 合法输入内的增强、视角、记忆；有深度条件才考虑 3D | improving-observations-and-memory |
| 训练分布外偏离，且专家可标注偏离状态 | 开发训练侧的纠错数据，而非复制失败动作 | learning-from-policy-failures |
| 有兼容权重或原生在线训练器 | 小测迁移成本；在线 RL 必须有可用反馈与吞吐 | adapting-pretrained-policies、learning-from-policy-failures |

顺序可改变：固定数据榜单不采集；原生 RL 仓库不强造 BC 数据集；资源缺失先找官方资源或声明边界。没有普遍最容易 SOTA 的算法，上表是当前预算约束下的工程推断，不是论文证明的统一排名。

## 给下一实验一张简短说明

写明：当前证据、可证伪假设、允许修改的变量、对照、最低有效训练量、开发指标/样本、预计采集/训练/评测成本、保留/停止条件、checkpoint 与数据身份、准备展示的失败/成功 demo。只调一个因素有利于解释；组合方案也可尝试，但不能把组合增益归给单项。

先用小试确认可运行，再用足以产生学习信号的预算比较。短试 loss 只能作遥测，未经校准不能跨模型排名。主 Agent 可申请局部延长/重分配、提交受支持的长期作业或取消停滞作业；这些是已有执行接口能力，不是 skill 新授予的能力。每仓库 24 GPU 小时等总硬限不变，预留正式复评和媒体成本。

阶段性 RUN.md 说明“为什么这轮值得做、结果改变了什么认识”，而不是罗列参数。失败也保存稳定证据 ID，交 Fix 后复验原操作。
