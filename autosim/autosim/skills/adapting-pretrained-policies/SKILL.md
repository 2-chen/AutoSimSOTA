# 在预算内适配预训练策略

借鉴 [OpenVLA-OFT 论文](https://arxiv.org/html/2502.19645v2) 的高效动作预测与微调思路，不将其公开分数当成本仓库实测或当前排行榜。迁移的首要问题是兼容性和资源，不是模型名称。

## 先找到完整而可信的资源

先查已显式挂载的资源，再查项目官方文档、发布页和作者链接的权重仓库。记录版本、许可、文件大小、校验信息、模型结构、tokenizer/processor、动作头、统计量、任务/机器人约定。允许网络访问时由有权限的执行路径下载到 run-local 位置；鉴权/许可缺口要明确说明，不猜 URL、不搜集无关私人文件、不自动上传原始数据。

只找到源码不等于找到权重；只找到权重也不等于支持当前动作空间。无匹配权重可选择预算内从头训练的原生小模型、正式适配动作头，或推迟该方向。不能隐式随机初始化缺失层后称完整加载。

## 小测再投入

先原生加载/推理，再作少量真实训练更新测峰值显存、step/s、数据 I/O、评测吞吐；估算下载、转换、训练和确认的总成本，说明误差。LoRA 降低可训练参数量，不保证单卡足够或训练很快；量化须检查当前训练路径支持情况。

OFT 官方 FAQ 的训练设置使用 8 张 80GB A100/H100，耗时 1–2 天，不能据此承诺每仓库 24 GPU 小时复现其完整结果。[计算需求](https://openvla-oft.github.io/)（Frequently Asked Questions）。本地探针而不是论文硬件表决定是否开工。

优先保留可工作的原生基线。预训练候选与从头训练、继续训练的收益/成本分开报告；使用额外预训练数据时标明数据权限和比较口径。模型切换本身不是优化完成。

## 保留/停止

若最小 batch 仍 OOM、加载语义无法核验、预期训练超总预算，或需要协议禁止的传感器/数据，就记录边界并返回主 Agent 选其他方向。资源问题进入 Fix，不能用伪造权重、缩短正式评测或更改成功条件来“跑通”。
