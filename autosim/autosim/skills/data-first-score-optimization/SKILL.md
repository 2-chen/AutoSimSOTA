# 数据优先的自动提分

交付是 best 策略、原生分数和可追溯数据，不是调查篇幅。主 Agent 依据仓库证据选择执行路径，执行器只核验协议、身份、权限和总预算；以下是决策指引，不授予额外工具权限。

## 先让一个分数成立

保留兼容的原生策略家族，优先已有环境、权重与合法训练数据，做能辨别故障的最小原生试验，随后完成可比较 baseline。读源代码直到下一条命令的前提清楚就行动，不为可选组件重复调查。短计划可以没有新算法假设；模型回合超时不是仿真故障。

阶段必须分开：环境探针通过 → 策略加载及 rollout 可核验 → baseline 有效 → candidate 比较 → 留出确认。短训练探针不冒充收敛基线。未知资源先用 `inspect_workspace_resources` 查看实际挂载的元数据，不把空占位目录当成没数据。

## 用失败选择数据，而不是盲目堆量

从开发 rollout 的真实行为找瓶颈：覆盖不足、动作/观测错配、抓取失败、精细接触失败、漂移后的恢复、长序列遗忘等；类别由当前任务证据决定，不是预置 benchmark 标签。先排除策略身份和输入接口错误，否则采集可能只掩盖错误。

选择合法数据路径，可按需阅读 `connecting-native-data-collection` 与 `targeting-simulation-data`。优先一个能完成“采集 → 转换 → 实际 loader → 训练 → 同协议评测”的小候选，不等待所有采集路线都完成。没有自动专家时，可以使用已有策略自举或轨迹适配，但必须验证其前提；都不可用时，改做原数据清洗、去重、重采样或小规模训练改进。

可通过 `update_research_plan` 的可选 `data_strategy` 保存 route、why、targets、producer_to_loader、evidence_refs、next_probe；这是模型计划，不是采集通过证明。把开发失败与可控训练场景参数、正确动作来源、数据格式和实际消费路径连接起来。不要在协议冻结后才发现整个 collector / converter 边没有登记。

## 按真实收益扩大

保留 best checkpoint 和原数据身份，记录尝试/成功/接受/训练消费的区别。小批次出现产出与可比较收益后才扩大；新增数据会改变分布和训练曝光，避免仅因样本更多就把收益归因于覆盖。评测失败先修复原操作，不随意换策略家族和不匹配权重。

用真实吞吐估算采集、转换、训练、评测成本。Agent 可提交已核验的长期原生作业，在总额度内调整局部窗口；不要反复启动相同短时限试验，也不要为研究一个可选方向耗尽确认预算。保持固定评测、保护 held-out，不用确认集的失败反向设计采集。

## 候选池空不等于仓库不可运行

以 `remaining_candidate_rounds` 判断开发分配，`next_round == planned_rounds` 仍有最后一轮；round_count 包括 baseline 和失败记录，不是剩余额度。没有可选旧 idea 时，Main 可以根据当前源码通过 `propose_research_idea` 提交新的具体候选，不必等待再次批量生成。声明轴与真实 parser 的连接尚未证明时，不能猜分组名到原生 CLI 的别名；调查实际消费者，必要时选择合法的源码/训练优化路径。

代码候选同样需要真实学习工作量。用 `run_the_loop(idea_label=..., training_settings=...)` 显式给出经声明或验证调用者输入支持的局部预算，不能依赖旧 smoke 默认值。此前候选在训练前被拒绝时，保留其失败记录与回退；若原因已修复并有新实验依据，可以用新标签重新审核，不要原地改旧分数。框架提供预算输入的能力不是某个优化方向有效的证明，不通过无效补丁绕过审核。

官方参考是独立核验项，不是本地刷分的前置条件。选择的公开模型族必须与实际加载链一致；资源引用使用明确 run/checkout-relative 路径，消除歧义后再核验来源。缺引用前缀、理由过长或空候选池不是系统基础设施故障，也不是缺资源的证据。

如果新数据产出为零、质量或消费核验失败、得分不改善，应缩小目标、修连接、回到保留的 best 或改走已有数据优化。系统可以报告明确的外部资源阻碍，但不能以文档更新代替执行成果。
