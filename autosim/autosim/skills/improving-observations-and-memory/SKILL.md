# 改进观测与记忆

先排除接口错配，再判断失败是否与观测有关。方法假设须由训练/开发侧证据支持，不能从最终留出失败倒推修改方案。

## 从便宜可逆的实验开始

同模型同训练预算比较原配置与一种训练增强，例如实现已支持的 crop、颜色扰动。增强不能裁掉唯一目标、破坏语言颜色指令，或在没有同步变换时改变动作坐标。训练随机化不是扩大测试协议范围。

从本地已支持的轻量 crop/shift 起步，按实际样本检查强度；旋转/翻转和强颜色变化不默认启用。[DrQ](https://arxiv.org/abs/2004.13649v4) 提供像素 RL 中增强改善学习的证据，迁移到 BC 是待验证假设，不等同实现完整 DrQ。序列增强需考虑时间一致性，多视角/深度需保留模型依赖的几何对应；不把“全部视角同样裁剪”当跨模型规则。

冻结 encoder 缓存特征可减少重复计算，但前提是明确选择冻结、预处理稳定且缓存身份匹配。encoder 在更新、随机增强变化或训练态统计变化时，长期缓存会改变学习算法，应禁止旧缓存复用或作为显式新假设比较。训练增采后也要核对新样本进入预处理/缓存和真正 batch。

如果协议允许已有多视角或 proprio 输入，检查新增信息是否真进入模型；添加输入常常需要重训或兼容预训练头，不能在 eval 临时补一维。若速度/接触阶段依赖历史，比较合法的 frame stack、RNN 或 Transformer 历史机制，并验证 reset、mask、时序与相应训练预算。

深度/点云只有在允许的传感器、有效标定、单位和坐标系齐全时才列候选。DP3 使用稀疏点云表征与扩散策略，并在多种仿真任务中评测；这是有条件的方向，不是给 RGB-only 协议添加特权状态的理由。[官方项目](https://3d-diffusion-policy.github.io/)

## 证据与停止条件

画实际训练样本变换前后图，记录视角/输入身份；图只证明输入处理，效果仍由同开发协议评测决定。对增强强度、历史长度或表征做小规模单因素比较，统计显存、训练吞吐、推理延迟和失败类型。

没有可用深度/标定、权重不兼容、改动违反输入协议，或预计训练挤占最终复评预算时，记录推迟理由并转向低成本候选。不要把所有仓库改成同一种观测结构。
