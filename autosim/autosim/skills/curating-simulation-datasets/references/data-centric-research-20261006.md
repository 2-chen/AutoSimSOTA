# 围绕数据建设 AutoSimSOTA：调研、实现审计与执行设计

日期：2026-10-06。范围：可复现的具身仿真仓库，优先机械臂任务。只使用论文、作者项目和官方技术文档作为外部依据；本机源码审计与方案推断另列。不启动实验、不处理现存数据、不安装新的数据平台。本报告新增的技能与指引，不等于下面的数据基础设施已经实现。

## 1. 结论：从“每轮数据目录”升级为“持续积累的数据资产”

数据路线应该同时回答六个问题：缺什么行为、谁提供正确动作、需要多少有效覆盖、怎样处理才不损害语义、如何保存并复用、是否真正改善策略。采集数量是手段，训练实际消费和同协议表现才是反馈。实验没增分不等于数据没价值，更不构成删除原始数据的理由。

建议保留现有 Main + Resource/Init/Fix/Ideator/Supervisor/Recorder 职责，不先增加常驻模型进程。Resource 可在数据问题下承担“数据资产调查”职责，Main 维护数据策略；确定性工具处理索引、封存、字节身份与消费核验。不要让 LLM 逐帧整理文件或反复扫描整库，也不要让固定 benchmark 规则决定采什么。

优化目标分两层：科学层是可信开发指标与泛化，工程层是取得有效增分所需的采集、转换、训练、评测和存储成本。不同成本单位不直接相加为一个无来源总分；可以报告每 GPU 小时的指标变化、每接受 episode 的耗时、每新增覆盖的字节等，带上成本口径和不确定性。

## 2. 相关技术告诉我们什么

### 2.1 数量与多样性不是同一个变量

[Data Scaling Laws in Imitation Learning](https://data-scaling-laws.github.io/) 对环境、物体及每配置示范量做了实证比较，发现其研究条件下，多样性与重复量对泛化的作用不同，重复量存在边际收益递减。这个结果支持“分别测覆盖和重复量”，不提供任意仿真任务的通用最优配额。

**方案推断：**第一次采集小试同时记录场景条件和接受轨迹，随后比较“补已有条件数量”与“扩展一个合法覆盖维度”。seed 数、文件数和视频帧数不直接当覆盖。基本技能仍欠学习时，同分布增量依然合理；任务定义不允许扩展物体/动力学时，不以多样性为由越界。

### 2.2 数据质量依赖策略和状态—动作关系

[Data Quality in Imitation Learning](https://papers.neurips.cc/paper_files/paper/2023/file/fe692980c5d9732cf153ce27947653a7-Paper-Conference.pdf) 从分布偏移讨论动作分歧与转移多样性的相互作用，说明仅增加状态多样性并不总能提高效果。它不支持仅按“成功/失败”或“轨迹短/长”判断全部训练价值。

**方案推断：**采用分层质量诊断，先查损坏/截断和动作语义，再查标签来源和任务成功，最后验证当前策略的下游收益。稀有困难数据、必要静止和接触等待应保留，不用单一长度/loss 阈值不可逆删去。

### 2.3 针对性采集必须有正确动作供给

[DAgger](https://arxiv.org/abs/1011.0686) 强调学习者访问状态上的专家标签；[DART](https://arxiv.org/abs/1703.09327) 研究带受控噪声的示范采集。二者启发恢复数据的设计，但有专家能给正确动作、原生任务允许干预等前提。给离线 action 加噪声没有重新执行和对应正确标签，不等于恢复示范。

[MimicGen 官方文档](https://mimicgen.github.io/docs/introduction/overview.html) 和 [TaskSpec](https://mimicgen.github.io/docs/modules/task_spec.html) 提供少量示范到新情境的生成机制，但依赖对象/子任务信息及环境接口。不能把适配轨迹复制为多个文件就叫新覆盖，也不能假设它能接任何仿真仓库。

**方案推断：**优先检查现有原生专家，其次检查轨迹适配和成功策略自举的真实前提。独立专家不依赖当前策略得正分；成功自举有低产出风险。普通 BC 不把失败动作直接当专家目标；失败记录可用于诊断、带专家重新标注的纠正，或协议允许的 RL。

### 2.4 混合与选择本身可以成为优化方向

[Re-Mix](https://arxiv.org/abs/2408.14037) 研究机器人数据域的权重学习，其主要场景是大规模多域模仿学习预训练。适合借鉴“实际采样质量比目录占比重要”，不适合直接把完整 DRO 训练加到每个小任务。

[DataMIL](https://arxiv.org/abs/2505.09603v2) 使用任务相关代理和 datamodels 做策略感知的数据选择；[QoQ](https://arxiv.org/html/2603.09056v1) 使用影响估计，并聚合到轨迹级以减少噪声。它们给出超越视觉相似度的选择方法，但需要目标示范/代理、梯度或模型计算，并非免费过滤器。

**方案推断：**先实现可追溯的来源分组、抽样计数和可逆选择视图，比较廉价过滤/混合。只有候选数据较大、重复训练成本明显且代理与开发 rollout 有相关性时，再尝试梯度相似度、影响估计或 learned mixture。用训练侧验证数据选择，不使用最终 held-out；代理分数不取代正式 rollout。

### 2.5 通用的是语义描述，不是唯一落盘格式

[robomimic 数据文档](https://robomimic.github.io/docs/datasets/overview.html) 使用 HDF5 存放轨迹、环境参数和划分；[回放教程](https://robomimic.github.io/docs/tutorials/dataset_contents.html) 区分观测展示与动作回放验证。格式可读和画面正常不能独自证明动作能重现行为。

[RLDS](https://github.com/google-research/rlds) 明确 episode/step 结构、截断与 terminal 区别，并能标记无效 episode；[LeRobot v3 文档](https://huggingface.co/docs/lerobot/lerobot-dataset-v3) 将时序表、分片视频和索引元数据分离，episode 边界由元数据确定，并要求正确完成 writer。二者有助于设计统一索引，不要求当前仓库更换原生 loader 或升级版本。

**方案推断：**框架定义最小语义 manifest，原生数据继续采用其支持的 HDF5/Parquet/MP4/Zarr 等格式。Init 按源码生成有限桥接，执行器只验证合同；未知语义不能由框架“自动标准化”。跨格式转换保留来源和损失说明。

### 2.6 版本与存储必须服务于复验，而不是仅留下 hash

[DVC 内部设计](https://doc.dvc.org/user-guide/project-structure/internal-files) 展示内容寻址对象、目录 manifest 和依赖/参数/命令相关的运行缓存；[DVC GC 文档](https://doc.dvc.org/command-reference/gc) 明确共享缓存回收需要覆盖所有项目引用，远端删除有不可恢复风险。可借鉴这些机制，不必给每个运行环境安装 DVC。

[Datasheets for Datasets](https://arxiv.org/abs/1803.09010) 提倡记录数据动机、组成、采集、处理、用途和维护信息。对本系统可缩成可查询的数据卡，不让写长报告拖延实验。

**方案推断：**数据索引、不可变字节与实验视图分开。以原始版本 + 转换/选择规则形成派生版本，跨 run 复用前重验许可、任务、控制语义和字节。单盘多个链接不是备份；seed 不是完整恢复材料。

## 3. 当前实现审计：已有基础，但还不是数据研究平台

| 方面 | 源码确认已有 | 实际缺口 |
| --- | --- | --- |
| 路线选择 | Main 的 data_strategy、采集优先提示与显式技能选读 | 计划不证明 collector 已接通；历史 run 仍可能仅有 train/evaluate |
| 版本登记 | data_versions.py 中不可复用 ID、字节身份、独立用途/loader 审核 | 未统一保存 producer attempt、类型、parent、质量/覆盖和许可 |

| 规模 | 当前注册最多 64 GiB、10000 目录项的有界扫描 | 多次整体身份计算；缺少分片索引、增量验证和大数据恢复 |
| 保管 | storage_lifecycle 拒绝 collect/prepare_data 生产者的自动 payload GC；注册数据引用被保护 | 防误删不等于跨 run 可发现、独立备份或统一归档 |
| 可视化 | Recorder 有版本/文件数/字节表，测量附消费状态 | 缺少来源/有效轨迹、隔离原因、覆盖、曝光、血缘和数据收益对照 |

审计入口：[data_versions.py](../../../research/data_versions.py)、[prepare.py](../../../research/prepare.py) 的 `_step_register_data_version`、[storage_lifecycle.py](../../../research/storage_lifecycle.py)、[recorder.py](../../../research/recorder.py)。当前 register_data_version.version **只接受** id/dataset_ref/source_refs/reason，不能把本报告提出的字段直接塞进旧接口。直接调用登记函数的测试也不等于生产数据已有真实采集来源。

当前数据身份主要回答“字节是否相同”，科学语义主要依赖源码审核和 Agent 调查。registered 的文件数不能猜 episode 数；not_required 只说明未选择显式新版本，不证明源数据优质或没有隐式默认数据。没有数据消费证据时不应追加训练掩盖接口缺陷。

## 4. 数据类型：相同目录不能使用相同训练规则

以下分类是 Agent 调查框架，不是执行器按 benchmark 分支。

| 类型 | 用途/前提 | 需要区别的证据 |
| --- | --- | --- |
| 官方或已有专家示范 | 优先建立原数据基线 | 任务/版本、训练许可、动作表示、真实 loader |
| 原生专家新示范 | 同分布扩量或合法覆盖 | 实际生产者、规划/执行结果、成功标签、独立场景 |
| 恢复/专家接管 | 弥补策略偏离状态 | expert target 与 executed action、接管段、前置状态 |
| 策略成功自举 | 有成功产出的训练侧 rollout | 策略身份、原生成功、接受偏差、训练/评测隔离 |
| 次优或失败交互 | 诊断、再标注或合法 RL | 不默认送入普通专家 BC；reward/terminal 含义 |
| 轨迹适配/合成示范 | 有环境/对象/专家语义前提 | 原示范 parent、变换、真实执行或合成机制、损失 |
| 只有视频/观测 | 可视化或匹配方法的辅助学习 | 不伪造 action；传感器/标定/来源 |
| 损坏/未完成/不兼容 | 隔离并定位生产/转换故障 | 原始身份、失败原因；不记为有效轨迹 |

一个 episode 可以包含不同控制来源，不能只在目录层标成 expert。合法用途也可能重叠，采用显式用途/来源标签，不把类型标签当固定有效性阈值。

## 5. 采集量：围绕产出、覆盖、曝光和边际价值决策

### 5.1 必须分开的计数

Agent 应请求或调查：目标接受数、原生尝试数、规划失败/运行失败/过滤数、完整接受 episode、独立来源轨迹/场景、有效帧、训练序列数、实际读取/抽样量。无法观测的计数写 unknown；记录计数者源码和回执，不靠 shell 回显计划数。

长轨迹的帧多，不等于独立任务覆盖多；同一原轨迹的大量重叠窗口不能当大量独立示范。近重复比例须说明算法、阈值和验证样本，不能变成通用删除准则。加权的有效样本统计也只是曝光代理，不消除时序相关。

### 5.2 一次可执行的小试

1. Main 提出当前一个可反驳的数据瓶颈，保留原数据基线和 best。
2. 选择合法动作供给与一类干预，按原生单位安排最小有意义批次；工作量不是固定 10/100 条。
3. 观察真实产出、接受率和字节；转换后用原生 loader 读取可追溯 batch。
4. 训练新候选，核验产物实际加载并走同一正式评测；记录实际总成本。
5. 决定扩大、改变类型/目标、混合/清洗，或不增采续训。失败交给具体连接的 Fix，不能把失败重复算作新数据研究。

这是建议形状，不阻止原生在线 RL、自举前先训练或固定数据任务的合法路线。冻结前接通必要边；旧冻结会话缺 collector/转换/数据轴时不得偷改协议。

### 5.3 自适应批次与停止

按本次耗时/接受率估计下一批，并加上转换峰值、训练和完整评测时间。内部重试没有上限的采集器尤其要限制尝试/墙钟而非只设成功目标。后续批次优先提高边际覆盖或修正已证实标签问题，不默认倍增数量。

达到接受目标、总预算、安全存储边界、专家持续失效或已没有可检验收益时可以停止/缩量。停留在低分且数据接口错误未排除时，优先诊断而非宣称饱和。开发指标噪声大时，结论记为不确定，不靠 held-out 重复查询挑选批次。

## 6. 处理：raw 不变，选择和转换有版本

### 6.1 分层质量核验

- **Q0 完整性：**writer 关闭、容器可读、帧/step 范围一致、字段齐全、NaN/Inf、截断和成功标记来源。
- **Q1 语义：**观测/动作时间对应、单位/坐标系、绝对/增量控制、gripper、相机、终止/时间截断、归一化与统计来源。
- **Q2 行为：**专家/动作标签可信、合法接触/等待、覆盖与近重复、针对性恢复是否真实。
- **Q3 消费：**实际选中数据/序列、分组抽样、训练更新和源曝光，排除默认旧目录与缓存。
- **Q4 效果：**同协议指标、开发切片、对照、成本和不确定性；Q0–Q3 通过不保证提升。

质量等级是报告结构，阈值和原生语义由 Agent+源码审核决定，不能把 Q0/Q1 的工程拒绝与 Q2 的研究判断混成万能规则。检查动作是否越界应使用本仓库的真实控制接口，不统一假设 [-1,1]。

### 6.2 可逆的数据视图

优先保存 episode 选择 manifest、分组权重和排除原因，避免修改/删除 raw。保留完整序列和来源链：同一个 parent 示范的窗口/适配子轨迹按组划分，防止近重复跨训练/验证。benchmark 原有固定划分不能自动重分。

训练统计仅从合法训练集合计算，并作为派生版本的明确输入；不使用最终留出数据，不无声复用旧 stats。转换/重采样/裁剪记录映射和不可恢复的字段。视频有损编码、丢深度或时间重采样都可能改变学习输入，不能只作为“存储优化”绕过研究审核。

### 6.3 混合与价值选择

小增量若按全库 frame 自然抽样，可能几乎没有曝光；均匀按 episode 又可能改变长短轨迹比例。先查真实 sampler 和读取计数，再比较一种来源比例。保留原分布检查遗忘；恢复片段过重也可能破坏正常 reset 行为。

从低成本到高成本考虑：原生完整性/语义核验 → 明确来源/失败分组 → 精确去重或可逆近重复分组 → 预算相近的混合/过滤对照 → 有可验证代理的数据价值方法。此顺序是成本建议，不是强制算法流水线。

## 7. 保管与复用：设计的是生命周期，而不是复制一个大目录

### 7.1 最小数据卡与血缘（待实现）

建议新的 versioned DataAsset 元数据包含：asset/version ID、内容 manifest 身份、类型和用途、所有权/许可、source run/producer receipt、source revision、任务/环境/控制语义摘要、parent IDs、转换/选择配置身份、训练划分身份、数量/覆盖/质量的来源 ref、备份与消费引用。大视频/轨迹不放到模型上下文；Main 看到短目录后请求分页元数据。

血缘至少能追溯：原始采集 attempt → 完整 episode/shard → 转换/选择视图 → 数据版本 → trainer 消费 → checkpoint → rollout → 分数。producer 成功退出、数据已注册、loader 已读、充分曝光和下游增分是不同状态，分开显示。

### 7.2 存储分层

| 层 | 默认处理建议 | 不能假设 |
| --- | --- | --- |
| raw 与核心元数据 | 只读保留、优先归档/备份、保护来源 | hash 或 seed 能恢复字节 |
| 不可再生转换产物 | 作为受保护版本保存 | 转换可重复就一定无损 |
| 可再生训练视图/解码缓存 | 记录完整重建依赖，之后受控维护 | old/big 就可删除 |
| 展示代理视频/缩略图 | 与学习视频分开，按展示成本维护 | 演示压缩可覆盖训练原片 |
| 失败/隔离产物 | 保留原因与必要内容，定义明确保管策略 | 失败轨迹全部无价值或必须无限保存 |

当前自动 GC **不覆盖数据**，本报告不改变授权。数据迁移、上传、隔离后回收或共享缓存维护需要新合同和操作者许可，先列精确对象/引用/恢复条件；跨 run 引用、未知 writer、未完成事务都要保护。

### 7.3 分片、内容寻址与增量核验

建议先用 native episode manifest，再按当前格式支持的 shard 封存。每片有字节摘要和 episode 边界，根 manifest 包含顺序、schema、划分和选择规则身份。只封存 writer 已关闭的片，活动片不可用最终 hash 冒充已发布。

新版本复用未变对象；读取时验证实际消费片及根身份。不可变受控对象可缓存哈希，普通可变源文件不能只靠 mtime/size 放行。目录身份算法有显式 schema version，不能用新 Merkle 算法悄悄替换现有 artifact_identity 的旧版本身份。

CAS 解决字节复用，不解决语义兼容和备份。run 工作目录用只读资源视图/COW 连接，避免把可写 raw 硬链接进多个实验。当前大数据上界在增量合同完成前保持，不直接放大 64 GiB/10000 项限制后全库反复扫描。

### 7.4 原子发布、断点续采和转换缓存

新数据先写 staging，验证完整性与原生接受结果后封存 manifest，再原子发布注册 ID。attempt 失败可能有已封存完整 episode，需显式采用，不能把未关闭文件混入新版本。恢复以已提交 episode/内容身份去重，保留原失败和预算。

转换缓存键应绑定输入内容、所选 episode、转换代码与依赖、参数/输出格式、相机/动作语义、统计与划分，而不是文件路径或任务名。模拟渲染重建还需环境/资产版本及重建验证；非确定性作业不因同 seed 就自动命中。命中仍核对字节和消费者，不用转换成功替代实际 batch。

## 8. 职责安排：让 Agent 决定，工具执行确定性工作

| 职责 | 交付 | 不承担 |
| --- | --- | --- |
| Main/Scheduler | 数据假设、类型/目标/量、局部预算、停止/复用决策 | 逐帧遍历和凭空提供正确动作 |
| Resource（按需数据资产任务） | 原生生产/资源/许可/语义/已有数据短目录 | 未授权启动采集/上传 |
| Init/Fix | 冻结前桥接、writer/converter/loader 连接或失败修复 | 暗换数据根、覆写 raw/评测 |
| Ideator | 数据与不增采对照候选，成本和预期影响 | 为凑候选编未声明轴 |
| Supervisor | 用途、划分/泄漏、语义/身份、来源审核 | 由成功标签担保增分 |
| Recorder | 数量/版本/覆盖/消费/效果对比与真实 demo | 编造缺失计数或人手替系统录像 |
| 确定性执行器 | 封存、索引、字节核验、事务/总资源约束 | 通过 repo 名规则选研究路线 |

不需要立即新增第九个常驻 Data Agent。若一轮有多个独立数据问题，可在现有授权调度下使用 Resource/Monitor 技能化分工；任务要交付短证据和具体下一动作，不做连续多轮空泛调研。数据基础设施成熟后再评估专职 Data Steward 是否能减少总调用成本。

## 9. RUN.md：让数据变化和效果读得出来

优先展示一张数据变化/实验对照表：版本及来源、目标瓶颈、尝试/接受、独立条件、有效帧、实际曝光、采集+处理成本、关联训练、正式开发分数。只有实际有证据的字段填数，计划、估计和 unknown 不混为实测。

按问题选择最多几个有用图：原数据/新增数据的合法条件覆盖、失败/隔离原因、来源采样曝光、累计接受与字节、数据量/成本对应的开发分数。当前没有通用图生成器和计数器，须先落实 manifest/报告投影，再由 Recorder 提出展示请求。

代表 demo 区分专家采集、策略训练侧 rollout 和正式开发评测；有稳定 episode/producer 来源再显示。只有观测录像能说明数据外观，动作回放才可能检查动作执行；二者都不取代策略评分。不要为图好看篡改原始轨迹或展示成功样本代替整体统计。

## 10. 实施优先级与验收

### P0：决策与资产保护先行

本轮先交付两个按需技能、Main 的简短数据生命周期指引和本报告。后续优先实现最小 DataAsset/episode sidecar：来源类型、真实 producer receipt、parent、可观测计数/unknown、用途/划分与保护引用；与现有 data_versions 保持向后兼容，旧 unknown 不臆补。冻结前确保原生采集→转换→loader 可表达。

验收：源数据 hash 不变；失败/截断与有效轨迹分开；登记不等于质量/增分；源码/许可/划分不匹配拒绝跨 run 复用；旧版本仍可解析。

### P1：原生数据健康、可逆处理与报告

按 Agent 选择的源支持接口运行 batch/有限样本/动作回放检查，封存诊断。选择/混合视图保留 parent 和分组，不改变 raw。记录实际读取/来源曝光并在 RUN.md 对照；数据工具缺字段有具体 Fix 证据，不使整个环境准备重做。

验收：故意错位、截断、旧 root/缓存、相机/动作错配能被消费者证据区分；分组泄漏检查不靠文件名；至少一个数据版本实际消费并完成原生评分。诊断 CPU/GPU 成本进入账本。

### P2：事务发布、增量分片和复用

实现活动/已关闭 shard、原子发布与中断核对；建立可分页数据目录、parent 图、内容寻址/只读挂载和正确转换缓存。旧 identity schema 保留，新 schema 显式协商；扩展容量之前验证分片核验和 O(新增内容) 行为。

验收：kill writer/转换后不发布坏版本；重试不重复采已提交 episode；复用不写源数据；不同控制语义同名数据不误命中；实际消费片被篡改即拒绝；共享数据仍在引用时不能回收。

### P3：自适应采集和数据价值候选

Main 从实际覆盖、接受率、开发诊断和成本更新批次/类型，保留原数据/不增采续训对照。优先廉价分组/权重，再按条件尝试 DataMIL、QoQ 或原生恢复/适配。缺专家、固定数据或低产出时允许合法回退。

验收：至少两个资源可复现仓库不加 repo 分支完成“小试→消费→训练→评分→下一决策”；数据候选退步后合理修连接/回退，预算内留下可复验数据而非无限采集。

### P4：归档、备份与更大范围复用

明确存储位置/介质、授权和费用后再接远端；验证恢复读取而非上传回执。自动维护只能触及精确授权的可再生缓存或明确策略对象，raw 和全局引用保护默认不降低。长期数据价值不等于无限磁盘，保留/归档策略需成本与用途依据。

验收：跨 run 引用与所有权、原生恢复、失败隔离、审计日志及“备份损坏/不可达”反例完整覆盖。单仓库增分不宣称任意具身仓库数据通用。

## 11. 范围与本轮交付边界

本轮把相关技术整理成可用决策指引，并维护总规划；不实现/宣称完整 CAS、数据湖、自动上传/删数据、影响函数算法或通用采集器。真实 RoboSyn 新增采集闭环仍待接入验收。执行优先级先资产来源和连接可靠性，再大规模优化，避免为了建设平台再次长期卡住没有实验结果。
