# 把数据干预变成可比较的实验

数据价值取决于任务、策略和实际采样，不由条数、成功标签或画面好看单独决定。以下是 Agent 决策方法，不是固定采集配额或自动清洗执行器；保留原数据和已冻结评测。

## 先分清用途和供给

从当前源码与回执区分：已有/公开专家示范、原生专家扩展、恢复/接管轨迹、成功策略自举、次优/失败交互和只有观测的视频。失败交互可供诊断或合规 RL，不能当作正确 BC 动作；成功自举不是独立专家。任务成功不证明每个动作优质，只有视频不证明有可训练动作标签。

从开发失败或合法训练覆盖提出一种有区分力的目标：基础动作缺数据、初态/物体覆盖、接触精度、偏离后的恢复，或者数据接口错误。参数、动作来源与接受标准由当前任务代码推导；任务定义之外的动力学、传感器或随机化不能因为能生成就加入。

## 数量由小批证据决定

先以原生单位做能完成的小批，分开记录请求目标、实际尝试、任务成功、完整且接受的轨迹、独立场景、有效帧/序列、实际 loader 曝光、总耗时和新增字节。计数缺失记 unknown；不同 seed 不自动等于不同覆盖。用观察到的产出率和成本安排下一批，同时留出转换、训练及完整评测窗口。

区分三个实验问题：增加同分布数量、扩展一种合法覆盖、改变质量/混合。先比较一种，不机械地同时增量、换 sampler、加训练步数。原数据继续训练是有用的计算量对照；沿用既有 baseline 的研究比较也要解释新增计算。覆盖接近饱和、专家低产出或同计算下无收益时可缩量、换目标或回退，不自动翻倍。

## 不可逆清洗改成可追溯选择

小试质量/同步不清楚时选读 `auditing-demonstration-quality`。exact-action重复诊断与文件内容重复、源demo族及目标覆盖是不同事实：图像不同可能有合法视觉增量，索引/hash不同也未必有新行为。逐条监督与场景信息来自原生记录，旧数据缺字段不事后补常量；MimicGen子孙分组、DAgger标签/历史与mask需各自消费者验证。

损坏、截断、字段缺失或动作语义不兼容进入隔离/排除视图，记录原因，不覆盖 raw。低质量、静止、长轨迹、稀有场景是待验证标签，不直接删去；静止可能是必要等待或接触稳定。精确字节去重与近重复行为分组分开，视觉相似但动作不同不能自动合并。按完整 episode/来源链分组划分，避免同一原轨迹的窗口或适配子轨迹跨训练与验证。

转换应记录输入身份、转换源码/配置版本、输出身份及损失信息。核对相机/状态与动作时间对齐、单位/坐标系、绝对或增量控制、gripper、终止语义、序列边界和归一化统计来源。不要统一设动作范围或把所有格式升级到最新版；通过当前原生 loader 检查实际 batch，必要时请求有预算的原生动作回放。

混合比例按真实采样单位解释。episode 数比例不等于 frame/sequence 抽样比例；记录来源/轨迹的实际读取计数。加权、过滤、恢复数据和 DataMIL/QoQ 等选择方法需走当前支持的候选接口；后者有额外梯度/模型开销，先验证便宜分组对照和开发代理，再决定是否值得实施。开发代理 loss 不取代 rollout 分数，不用 held-out 设计选择权重。

## 交付

现有只读原生检查可生成逐episode manifest与可逆Q0/目标条件选择：真实记录的条件/单位、来源族和动作供给缺失时保持unknown。共享文件不同episode不按文件hash误去重；保持完整来源组。视图本身不是native loader可消费的数据，派生、转换和batch仍需实测。

新前瞻对照用campaign v2的随机/规则/Agent目标等方法，冻结一个预算轴与共同因素；未完成数据arm时不提前确认。操作字段、部分失败登记、实际batch计数与明确边界都在[原生数据合同](references/native-data-contract.md)，用到时再读，不把整份合同加入常驻上下文。

失败驱动研究先用 `register_data_campaign` 保存开发 measurement、尚待验证的原因假设、原生获取/筛选方法、等接受数量的 targeted/random 对照、训练配方/种子与全成本口径。只改变目标采样时保持共同质量底线；要证明筛选作用，再独立比较目标相关筛选与无目标筛选。等总算力是另一研究，不能混称等数量。

原生生产/转换、登记和真实训练消费完成后，独立计分才调用 `record_data_campaign_arm`。同一测量不能代表两个方法或种子；声明种子/配方不是实际生效证明，需 Supervisor 查原生记录。注册假设不是执行、科学批准或增分，不为了填写表格重用旧成绩。仓库只有人工示范时明确边界，先考虑合法已有数据筛选，不编造自动专家。

在现有 data_strategy 和候选理由中写清目标、类型、供给、数量依据、接受/隔离标准、实际混合与成本预测；只使用接口已有字段和已声明轴。`register_data_version` 及消费 witness 证明身份/读取，不认证质量或曝光充足。用中文 RUN.md 展示数据版本、实际消费、同协议指标和真实样本 demo；未实现的统计/图表明确记为缺口。

需要登记本次生产/处理的数据、提交健康计数或实际来源曝光时，按需读 [原生数据合同](references/native-data-contract.md)。已有接口支持可选资产卡、封存原生 profile、parent/recipe 及 loader 曝光；原始格式、探针、过滤和采样仍由 Agent 依据当前源码设计，不由框架统一转换。无需为了旧数据兼容而重新生成全部元数据。

需要相关工作、成本选择依据与系统实施优先级时，按需读 [数据中心研究与资产管理调研](references/data-centric-research-20261006.md)。正文可独立使用；参考文档不自动加载，也不代表已实现数据仓库或价值评分器。
