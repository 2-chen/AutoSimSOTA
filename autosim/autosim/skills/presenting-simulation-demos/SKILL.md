# 展示有解释的仿真 demo

先明确读者需要观察的问题：环境能否运行、策略如何失败、两项策略有何行为差异，或训练指标是否变化。再选择能回答这个问题的已有产物。没有有效媒体时提交带理由的录制请求，由 Scheduler 和受预算执行器决定执行。

## 按来源选择

读取媒体清单和 producer 回执，核对 run、attempt、任务、策略、生成时间及可解码状态。优先使用本次原生评测已经生成的媒体；来源不全的文件只能说明“发现待核验文件”。

按运行预先约定的样本规则选片，例如固定诊断初始状态、首个成功或首个失败。保留选择理由；不能只挑成功录像。没有相应样本时说明缺失，不替换为旧 run 的视频。

第一次 reset/step 录像可以证明仿真链路可运行，标为环境探测。策略 rollout 录像需要对应策略身份；两条视频只有初始状态和任务条件可核验一致时才称配对比较。确认集媒体在结果提交前保持隔离。

## 写清楚看到了什么

每项媒体配一两句中文说明：什么任务和策略、能看到什么行为、它支持哪项判断，以及无法据此推出什么。不要以“精彩 demo”“效果明显”等形容词代替观察；看不到动作或没有观看权限时，不推测画面内容。

展示形式优先为可点击视频链接与从该视频实际提取的缩略图。用相对路径支持报告搬迁；注明时长和样本身份的可得信息。抽帧、解码及曲线绘制交给已有受控发布工具；不以生成图片或重演轨迹代替实录。

数据图要有实际数据、横纵轴含义、单位和范围。分别说明训练遥测与正式评测；缺少有效分数时不画成功率为零的曲线。错误日志里的版本号、随机矩阵计算结果和 seed 不是学习指标。诊断时间线或失败次数图可用于解释工程过程，但不能冒充学习曲线。

## 没有 demo 时也给有用说明

区分尚未进入仿真、缺少匹配策略、渲染失败、录制未接入、预算未分配、证据不可访问和核验未通过。尽量引用具体失败，例如“策略加载前就结束，因此本次没有 rollout 视频”；不要笼统写“暂无媒体”。

录制请求只描述观察目的、事件/策略引用、已有 DemoSpec 和所需产物；不附仓库专用命令，不提高预算，不改评测任务。一次媒体失败可保留原因并让研究继续，是否重试由 Scheduler 决定。
