# 把原生采集接到实际训练

这是方法指引，尚无跨仓库增分保证。由主 Scheduler 决定调查与实验顺序；在协议允许、无人采集可行且训练器能消费产物时，优先评估小规模数据改进实验。保留原数据的基线，依据实际增分和成本决定是否扩大采集。

## 责任与交付

主 Agent 可用 `research_task` 委派 `resource` 调查数据供给，也可自行调查。交付应包含：原生入口及配置来源、动作提供者、所需资产、训练划分、产物格式/位置、转换入口、训练 loader 的实际输入，以及尚未验证的连接。Resource 只读源码和回执，不启动采集；Init 负责接入期的配置与连接，Fix 定位具体失败，Scheduler 通过受控执行器运行原生阶段。研究开始后的源码修复走受审计的新候选。

把结论写进 `update_research_plan` 的问题、下一步和证据字段，区分：未知、发现入口但条件未满足、试采通过、训练消费已验证。缺少资产或 seed 列表是具体依赖问题，不足以证明仓库没有采集能力。

## 沿生产者与消费者调查

- 从当前版本文档、启动 wrapper、配置和任务实现追到实际生产者。辨别动作来自脚本专家/规划器、已有策略还是人工遥操作；策略自举还需已有成功率证据。
- 追踪命令参数、cwd、配置加载层级、资源路径、训练任务/seed、工作量单位和输出位置。成功 episode 数可能对应更多规划失败和重试；只复用 seed 的模式还可能依赖预先生成的轨迹。检查 wrapper 的转换、说明生成和缓存清理等副作用。
- 沿真实产物追到 converter 和 trainer loader。核对轨迹字段、相机/观测、动作表示、归一化与数据根目录实际解析位置。同一文件后缀或命令中的路径字符串不能证明数据兼容或被消费。
- 评测中顺带保存的视频/轨迹不能独自证明存在可用的训练数据供给；使用策略 rollout 作数据时，须明确训练侧的调用、数据权限和成功过滤过程。

在冻结研究声明前，核对原生采集器支持的可变参数与转换/训练输入，登记证据支持的 collection axes。不要猜通用参数名、凭空扩展采集能力，或给所有仓库套同一个流程。

## 用小试验证这条连接

让主 Agent 请求现有 `derive_a_command` 验证实际 `collect` 阶段，按原生单位选择足够完成一条轨迹的工作量和局部时限。CPU 调查子任务不能代替这次仿真验证；`submit_native_job` 当前只接收训练阶段，不能向它提交采集任务。

一次有用的小试需要拿到：本次 attempt 的轨迹身份、尝试数/接受数、成功过滤依据、实际耗时，以及原生 loader 能读取的观测/动作样本。若需要转换，确认转换的是本次数据；确认 trainer 的实际数据根、样本 ID 或数量变化，排除仍在使用原有默认目录/旧缓存的情况。

单纯生成文件或让 loader import 成功不算接通。若执行图不能表达转换或新数据输入，返回缺失的具体边与失败证据，交给 Scheduler/Init/Fix 处理；不要把旧数据训练结果记成新数据实验。修后复验原消费者。

## 优先尝试什么，何时扩大

已有数据可训练时先保存原数据基线，并尽早验证采集连接；基线后的候选优先包含一个有证据支持的数据干预，通常先补训练场景/物体/初始状态覆盖，再考虑重复数量。缺少可用训练数据时，小规模原生专家采集可以用于建立首个基线，但不能据此宣称相对原数据增分。

使用当前合法的 `propose_research_idea`/`run_the_loop` 接口：collection 设置须来自已声明的轴，候选需说明其数据如何进入训练、预期收益、采集与再训练成本。仅在输出和消费者连接均可验证时选择它。不要发明数据采集专用操作或绕过候选审核。

保留原数据身份、混合比例与训练预算，说明变化的是数据覆盖、质量、数量还是训练计算量。多数据未必提高分数；若没有收益、成功产出率过低或预计占满预算，主 Agent 应缩小批次、改变采集目标、改选其他方向或写明推迟理由。预算包含失败尝试、转换、训练、评测和媒体成本，总额仍为每仓库 24 GPU 小时等运行硬限制。

只使用协议允许的训练任务和随机化范围；测试 episode、测试反馈与 held-out 数据不进入训练或采集目标选择。固定数据协议、需要人工操作、缺资产、零成功率自举和原生在线 RL 都需要不同决策；对有依据的例外说明原因，无须为了“优先采集”强造独立 collector。

## 让人看到实验改变了什么

在中文 RUN.md 中解释为何采集或推迟、尝试/接受的数量、新增覆盖、数据实际进入哪个训练尝试，以及训练后开发指标是否改善。引用原生回执，并在有真实产物时展示有来源的视频或覆盖/质量图。采集成功率和视频展示只能说明数据供给，策略增分须来自后续正式评测。
