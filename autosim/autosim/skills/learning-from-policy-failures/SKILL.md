# 从策略失败中学习

先区分有专家标签和只有环境反馈两条路线；不是把失败轨迹直接作为 BC 正确动作。只能利用允许的训练/开发反馈，最终留出数据不进入研究回路。

## 有可查询的专家：纠错数据

[DAgger](https://arxiv.org/abs/1011.0686v3) 针对策略诱导的状态分布进行迭代数据聚合。迁移到当前仿真仓库前，验证专家能从策略偏离后的状态给出有效动作，而不仅能从标准 reset 完成脚本。

先在训练任务小规模运行当前策略，按预定规则选取失败前/偏离状态，由专家标注或接管恢复；保留动作来源、接管点、成功依据和场景身份。专家若只能从初态运行，改做相关训练场景的独立演示，不冒充逐状态 DAgger。

与同成本的普通新增演示比较；混合旧数据防止遗忘，并确认实际 loader 消费新数据。成功自举可能只复制策略已会的简单情况，需记录被过滤的尝试与覆盖，不能仅报保留样本成功率。

## 无专家但有合法反馈：在线微调

[DPPO](https://diffusion-ppo.github.io/) 研究了扩散策略的策略梯度微调，支持把模仿初始化后在线改进作为候选；不说明它适配任意模型或低预算必定获益。

先验证原生训练器、rollout/action/log-prob 接口、奖励与终止语义、并行环境资源和保存恢复。短探针测环境步吞吐、有效回合与奖励信号；有 BC warm-start 时可减少从零探索的不确定性，但要保留初始策略对照。

仅在协议允许时改变训练奖励或课程，并独立记录；评测奖励、成功条件、任务分布不变。特权训练信息必须由协议明确允许且不能流入部署策略输入。稀疏奖励长期为零、专家不可用或吞吐预算不成立时，应推迟而不是无限采样。

## 确认收益与解释过程

比较开发成功率、旧任务保持、采集/训练总成本，必要时展示固定开发初态的失败与恢复视频。当前技能没有新增执行器支持；采集、在线训练或长期作业若无法由现有接口表达，交主 Agent 处理能力缺口，不杜撰操作。保留原策略，候选经正式身份核验和复评后才能替换最佳版本。
