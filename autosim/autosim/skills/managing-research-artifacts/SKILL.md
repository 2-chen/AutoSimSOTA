# 把空间留给下一次有效实验

先说明为什么选读这项技能。不能用“文件旧、大、名字像 checkpoint”推断可删，也不能认为保存间隔一律可以随便增大。技能不授予删除、修改协议或增加预算的权限。

## 先读少量证据，再决定

调用 `inspect_storage` 查看可用空间、最近磁盘观测、分项占用、生产者稳定 ID 和既有清理事务。训练前沿保存源码调查：保存触发次数、最终保存、native best/早停、EMA/raw、optimizer/scheduler/RNG、别名、续训加载和实际计分选择。借用依赖的实现也要读，不能只看 wrapper 的 CLI 参数。

总览只采样最近 8 个生产者、每个最多 24 个文件，明确不是全集。用 `inspect_storage(evidence_id, offset, limit)` 分页查看同一生产者的完整文件目录（`next_offset` 为空才读到末页），不能把样本前缀当全部快照。扫描超过明确上限时报告不完整，不自动猜最后策略。

登记目录默认每页 24 组、每组展示最多 8 个文件名；`registry_offset/registry_limit` 控制登记分页，`registry_next_offset` 为空才读到末页。摘要明确给出组的完整文件数量和截断标志，执行时仍使用已登记的完整清单，不以显示样本代替清理目标。

估算：一次完整保存大小 × 保存次数 + 冻结策略 + 导出 + 视频/轨迹 + 缓存增长。测过的大小与推算分开报告；尽量先用配置、计数和文件大小筛选，不对每份大权重反复复制或哈希。未知项不能记作零。

原生作业的 `resources.storage_required_bytes` 可提交预计新增字节；`configure_storage_controls` 可以登记 `checkpoint_bytes` 和 `projected_bytes`。执行器使用保守协作预留，不预分配磁盘，也无法阻止其他宿主程序写入。估计不足时，运行监控仍要报告压力。

## 首选减少新增，而非事后救火

原生源码证明保存/日志参数不影响学习、评测和选择规则时，通过 `configure_storage_controls` 提交 `controls: [{flag: "原生长参数", value: 正整数}]`、理由和精确 `source_evidence: [{path, quote}]`。独立 Supervisor 必须确认 final/native-best、早停和恢复语义。参数名称与数值由当前源码决定，不套用仓库名或固定频率。

`path` 默认 checkout-relative；注册的外部依赖可用 `dependency:<索引>:<相对路径>`，索引来自已验证的 native_context。不存在/未注册的路径不是证据。源码变更使旧审核失效，需重新审核。学习率、训练量、数据和 evaluator 不是存储控制；想改研究设置需走原有研究接口。

框架冻结策略使用内容寻址复用，支持的文件系统尝试独立 COW，不把可变原生权重硬链接到计分副本。COW 不支持时会占用真实副本空间；不能把复用能力当成无限容量。导出仍保留真实文件，不输出只在本机有效的权重指针。

## 确需清理：先保护，再审核，再提交

存储登记只管理保留和 GC，不建立训练生产者身份，也不能修复 `checkpoint_ref` 的评测连接。若当前目标是复用已完成训练，先查 `verified_train_artifacts`、封存回执与计数，从保存/加载源码选择权重并派生评分命令；多 checkpoint 或多文件 bundle 本来就可能没有唯一的 `declared_artifact_ref`。目录预览截断时分页读完整清单，不因前缀看不到最终快照就重训。

登记 refs 只包含符合回收接口合同的二进制 payload；config、日志、计数、源码和证据继续保留，但不放进 GC 登记。完整恢复组需要这些元数据时，应在理由/来源中指出它们的依赖并保留原文件，而不是为了“完整组”请求删除元数据。注册校验拒绝后纠正请求，不把它解释为仿真不可运行，更不能通过放宽保护来修复身份。

1. 用 sealed `evidence_id` 和精确 run-relative `refs` 登记完整 payload 组。角色为 `terminal`、`resume`、`intermediate` 或仅限验证输出的 `verification`，解释原生语义并提供保存/恢复源码。独立审核登记；文件 ID 与字节指纹由执行器生成。相互依赖的 optimizer/RNG/权重应作为完整组，而不是删一半后声称还能续训。
2. 同一生产者的中间快照清理前，必须另行登记并保护 terminal 或可用 resume 组。当前计分/基线/最佳策略、已接受验证交接、注册数据、发布媒体等引用自动保护；terminal/resume 组不可由 Agent 降级成垃圾。
3. `plan_storage_gc(artifact_ids, reason, source_evidence)` 发起独立审核，解释为什么不影响计分、复验和恢复。清理计划列出实际文件，不接受目录通配符。
4. `commit_storage_gc(plan_id)` 只在操作者开启运行级自动回收时执行；再次核对引用、字节、路径、活动作业和终点/续训点。未授权时请求操作者、复用完成产物或申请明确的新存储位置，不绕到 shell 执行删除。
5. 若事务处于 `committing`，先 `reconcile_storage_gc(plan_id)`。它只确认已删/剩余内容，不重放删除；剩余内容需要新的登记和审核。不要把未知结果当成“什么都没发生”。

回收范围仅是明确由本 run 的原生训练/验证/媒体生产者生成、未被引用且已证明不需要的 payload。数据、源码、日志、配置、计数、账本和恢复证据不能清理。环境/共享缓存/下载缓存可能仍是依赖，当前回收接口不覆盖它们；调查后请求明确授权和另行受控维护。跨 run、源仓库与外部挂载不在范围内。

## 空间危险后如何恢复

运行器只廉价观测，不在每次轮询询问 LLM。危险时停止写入并封存磁盘证据，交给 Main/Fix。这不保证原生训练能保存最后状态：未保存更新可能丢失，必须检查已存在的完整恢复点。

空间/保存参数修复后优先复用完成训练或从核验的恢复点续训；保持累计预算、原基线和实验协议。恢复完整状态与仅权重 warm-start 分开记录。复验原失败操作，不以相同保存频率从头训练，也不因 ENOSPC 更换算法。

在中文 RUN.md 写清：空间为什么增长、测量和估算分别是多少、保留/回收哪些组及理由、实际删除事务链接、恢复损失与下一步。登记大小是逻辑体积；硬链接/COW 会使实际释放空间不同，不能夸大释放量。
