# 针对性采集：补哪些状态，谁提供正确动作

本技能指导 Agent 选择方法，不是通用采集器或 SOTA 承诺。执行仍走已核验原生阶段、合法声明与同一预算账本。

## 采集目标需要证据

读取开发 rollout 的失败记录和代表视频，结合合法训练数据的覆盖。关注失败发生前的状态与动作、物体/初始布局、遮挡、接触精度和阶段推进。不要仅按“任务失败”或单一 loss 排序；区分错误的数据接口与真正缺少的行为覆盖。

把目标写成可检验的连接：开发失败证据 → 可控制的训练条件 → 正确动作提供者 → 成功过滤 → 保存字段 → converter / loader。采集控制由真实任务代码和配置推导，例如初始状态范围、物体配置或扰动，但不是测试 seed 重放。新增恢复轨迹必须保持任务语义；任意设置仿真状态或改变物理条件不一定合法。

## 选择可用的动作供给

- **原生专家 / 规划器**：先接现有任务执行器，查实际动作空间、规划器资产与成功判据。规划成功和文件生成不等于 episode 成功或训练可用。RoboTwin 的官方采集文档展示了 task config 驱动的原生生成路径；当前仓库版本仍须读源码核验。[官方文档](https://robotwin-platform.github.io/doc/usage/collect-data.html)
- **轨迹适配**：有少量可回放成功示范时，考虑按对象／子任务坐标适配到合法的新训练情境，再真实执行和过滤。MimicGen 需要环境接口、对象信息及示范准备，不是复制 state 数组就能泛化，也不是任意 LIBERO 任务的即插即用专家。[官方教程](https://mimicgen.github.io/docs/tutorials/getting_started.html)
- **策略成功自举**：已有兼容策略且训练侧存在成功产出时，运行新训练初始状态并保留原生成功轨迹。没有自主 recorder 时，可在隔离源码中实现小包装器后再登记／核验，不因此宣称缺少所有采集路线。零成功无法自举；容易样本的幸存者偏差可能扩大瓶颈。BC 数据中的失败动作不是正确标签。
- **专家纠正 / DAgger**：需要专家能为学习者实际访问的状态给正确动作；专家只会从 reset 跑完整任务不意味着能接管任意失败状态。修正数据与成功自举分开记录。[原始论文](https://arxiv.org/abs/1011.0686)
- **只有人工遥操作**：没有人参与时不能假称已自动采集。调查其他供给路径，或暂用允许的已有数据清洗／重采样／下载。公开数据也须核对任务、格式、许可与训练划分。

## 小试必须走到消费者

用一次可完成的小采集批次验证实际输出：训练侧任务/随机化、动作提供者与 checkpoint、尝试数、成功数、接受数、拒绝原因、实际场景条件、数据内容身份。记录前后状态、观测和动作语义，而不只是视频。

转换后通过原生 loader 读取真实 batch，证明样本 ID、实际数据根、计数或采样曝光；排除默认旧目录和缓存。多条轨迹应有独立内容或不同合法场景，复制文件和重复回放不算新增覆盖。成功率、场景覆盖和数据质量是采集诊断，策略分数必须来自后续训练及同协议 rollout。

## 控制扩大与回退

先补对现有失败有区分力的覆盖，再比较质量、混合与数量。保留一部分原分布避免过拟合困难子集；比例由真实 loader 和试验决定，不是固定常数。人工难度标签不等于环境成功标签。

比较预算相近的原数据训练与数据候选，记录实际更新次数、样本曝光、初始 checkpoint 和总耗时，必要时做等计算量控制。若产出低、质量差、loader 不消费或得分退步，修连接、改目标或回退，不无界采集。所有失败尝试和转换成本计入同一运行预算。

展示代表性真实 demo 和覆盖/产出/质量对比，同时说明未核验连接；不借助合成视频或收集计数声称增分。
